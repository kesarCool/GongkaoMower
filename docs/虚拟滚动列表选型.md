# 虚拟滚动列表：机制说明与选型（含 `UICircularScrollView` 评估）

本文基于你提供的 **`UICircularScrollView`**（`ScrollRect` + 对象池 + 按槽位回收）实现做技术分析；选关及后续长列表可统一按本节选型。

---

## 一、`UICircularScrollView` 在做什么（机制）

| 环节 | 行为 |
|------|------|
| **依赖** | `[RequireComponent(typeof(ScrollRect))]`，`content` 下放 Cell 预制体（或场景里已有子节点作模板）。 |
| **Init** | 读 Viewport / Cell 的 `RectTransform` 尺寸、`Padding`、`Direction`（横/竖）、`Row`（每行/列格数）、`Spacing`；可选把模板 Cell 塞进池；**锚点**由 `ChildAlignment` 推到 `CheckAnchor`。 |
| **ShowList(sum)** | 按数据条数 `sum` 分配 **`CellInfo[sum]`**，为每条数据算一个 **固定槽位坐标** `Pos`；视口内槽位从池里 `Instantiate`/`Pop` 出 Cell 并回调 **`m_FuncCallBackFunc(index, go)`** 绑定数据；视口外 `Obj=null` 或回收进池。 |
| **OnValueChanged** | 每次滚动调用 **`UpdateList()`**：**遍历全部 `sum` 个槽位**，根据 `IsOutRange` 决定回收或从池取出并再次回调刷新。 |
| **点击** | `Func` 里给 Cell 根节点找/加 `Button`，`RemoveAllListeners` 后绑定 **`m_FuncOnClickCallBack`**。 |

**本质**：**可视区域外的 GameObject 不常驻显示（进池）**，这是虚拟列表的核心收益；**但逻辑上仍为「每个数据索引占一条槽位元数据」**，与「只保留固定 N 个 Cell、用 scroll 偏移映射 index」的经典 **Loop** 实现不同。

---

## 二、是否可行（选关场景）

| 数据规模 | 结论 |
|----------|------|
| **约 ≤ 300～500 关** | 一般 **可行**：`ShowList` 建数组与首次布局可接受；滚动时 `UpdateList` 全量扫一遍在移动端通常还能扛。 |
| **上千关 + 频繁滚动** | **风险明显**：`UpdateList` **每次 `onValueChanged` 都 O(sum)**，帧内若多次触发会放大开销；`CellInfo[]` 与 `sum` 同长度，**内存随关卡数线性增长**（虽比「每关一个实例」小很多）。 |
| **可变高度 Cell** | 当前实现假定 **Cell 宽高固定**，用统一 `m_CellWidth/Height` 排布；**不等高列表**需改坐标与可见判定，本脚本不直接支持。 |

**结论**：作为项目里已在用的方案，**选关列表在常见体量下可用**；若产品预期关卡数很大或要「微信小游戏上极致省」，建议换或改（见第四节）。

## 三、实现上的注意点（沿用该脚本时）

1. **Viewport 尺寸**：文件头注释已写：`verticalScrollbarVisibility` 为 `AutoHideAndExpandViewport` 时，**Start 前可能量不到尺寸**；建议先 `AutoHide`，首帧或首 `ShowList` 前再改回。  
2. **垂直方向 `IsOutRange`**：第二支路里上下界都用了 **`m_Cell_RectTransform.pivot.y`**（与横向用 `content` pivot 不完全对称），极端锚点/ pivot 下若出现裁切误差，可对比 `m_Content_RectTransform.pivot` 做一次统一。  
3. **`Button` 挂在 Cell 根**：若 Cell 内已有子 `Button`，根上再 `AddComponent<Button>` 可能和子控件抢射线；更稳妥是 **约定子物体上的 Button**，在回调里绑 `onClick`，避免动态 `AddComponent`。  
4. **`ShowList` 数量变化**：会重建 `m_CellInfos` 并尝试复用前 `lastSum` 段，逻辑较长，改需求时建议加单元测试或录屏回归。

## 四、方案对照（含本项目选型）

| 方案 | 特点 | 适用 |
|------|------|------|
| **本项目：`me.qiankanglai.loopscrollrect`** | **固定数量 Cell**，滚动时复用并刷新 `idx`；MIT，与 `com.unity.ugui` 搭配成熟。 | **本仓库新列表默认**（选关、背包等）。 |
| **`UICircularScrollView`（他项参考）** | 池化显示对象，但 `UpdateList` 易为 **O(sum)**；见上文第一节。 | 旧项目对照，不必迁入。 |
| **EnhancedScroller 等** | 功能全（部分支持不等高插件）。 | 有预算、需求超出 Loop 包能力时。 |
| **自研极简 Loop** | 少量 Cell + 手写 index 映射。 | 极简单列、不想引包时。 |

**依赖**：`Packages/manifest.json` 已添加 `https://github.com/qiankanglai/LoopScrollRect.git#v1.1.5`；首次打开 Unity 需联网解析；失败时可试 [OpenUPM](https://openupm.com/packages/me.qiankanglai.loopscrollrect/) 或检查 Git。

## 五、与 `LevelSelectPanel` 的衔接建议

1. **Prefab**：使用 **`LoopVerticalScrollRect`**（替换原 `ScrollRect`），Cell 为独立 Prefab（`LayoutElement` + `ScrollCellIndex` 桥接脚本）。  
2. **数据源**：在 `LevelSelectPanel.OnOpen` 内从 `TableManager` 拉取 `LevelWave` 列表长度，调用 Loop 包提供的 **`Refill`** / **`totalCount`** 等 API（以包内 `InitOnStart` / Inspector 为准）刷新列表。  
3. **绑定**：在 **`LoopScrollDataSource`** 实现里按 `idx` 写关卡标题、`levelId`、锁定态等。  
4. **点击**：Cell 内 `Button` 将选中 `levelId` 写入 **`SelectedLevelContext`**，再 `UIManager.CloseTop()` 或进入 `BattleLoading`。

## 六、一句话对照

| 维度 | `UICircularScrollView` | **LoopScrollRect（本工程）** |
|------|-------------------------|------------------------------|
| **可见 Cell 数** | 池化 ✅ | 固定少量 ✅ |
| **大数据下每帧成本** | 易 **O(sum)** ⚠️ | 主要 **O(可见)** ✅ |
| **接入成本** | 单脚本 | PrefabSource + DataSource + Cell 约定 |
| **选关体量** | 中等可 | 更合适 ✅ |
