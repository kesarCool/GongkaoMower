## 一、项目概述

《文字割草机》是一款面向微信小游戏平台的 **2D Roguelike 割草（Survivors-like）游戏**。玩家在封闭竞技场中操控角色，对抗以中文词汇形态出现的怪物浪潮，通过击杀收集能量、获取 Roguelike 卡牌升级，构筑技能组合直至通关或死亡。

| 项 | 值 |
|---|---|
| 引擎 | Unity 2021.3.22f1c1 |
| 渲染管线 | Built-in Render Pipeline（2D Sprite + Tilemap） |
| 目标平台 | 微信小游戏（WebGL / WASM） |
| 开发语言 | C# |
| AppID | wx27c7354ddadf45da |
| 上架时间 | 2026-06-25 |
| 开发周期 | ~2 个月（个人独立开发） |

## 二、核心玩法

### 2.1 基础循环

```
进入关卡 → 击杀怪物 → 收集能量 → 触发选卡 → 升级技能 → 继续战斗 → 通关/死亡 → 结算
```

### 2.2 操作方式

- **虚拟摇杆**：屏幕左侧拖动控制移动方向
- **点击移动**：点击屏幕任意位置，角色向目标点移动
- **自动瞄准/射击**：角色自动朝最近敌人方向攻击，无需手动瞄准

### 2.3 肉鸽选卡

能量槽满后触发选卡界面（暂停游戏），从随机 3 张卡牌中选择 1 张：

| 卡牌类型 | 说明 |
|---|---|
| **新技能（新）** | 获得一个未拥有的技能（最多持有 5 主动 + 5 被动） |
| **升级卡（升）** | 将已有技能升 1 级（最高 5 级，部分技能需羁绊被动才能升满） |
| **突破卡（破）** | 技能达到条件后触发质变（如满级换弹丸预制体） |

### 2.4 技能体系

| 类别 | 技能 | 说明 |
|---|---|---|
| 主动 | AutoProjectile（手枪/飞剑/符咒） | 朝最近敌人发射弹丸，多种变体 |
| 主动 | LightningStrike | 随机雷击场上敌人 |
| 主动 | LineBeam2D | 射线穿透伤害 |
| 主动 | OrbitingBlades | 环绕刀刃持续伤害 |
| 主动 | ThrowGrenade | 投掷手雷，范围爆炸 |
| 主动 | FieldGenerator | 持续力场光环 |
| 主动 | HomingMissile | 追踪导弹 |
| 被动 | 攻击力/暴击/穿透/破防/范围/移速 | 数值加成 |

### 2.5 英雄特质

6 种 Rare 阶位解锁的特质（角色独有被动效果）：

| 特质 | 效果 |
|---|---|
| 狂暴 | 击杀叠加攻击力 |

```

   ↑

   ↑

   ↑
```

**硬性规则**：

- 业务代码日志统一走 `GameLog`，禁止直接 `Debug.Log`

## 五、核心系统模块

### 5.1 刷怪系统（SpawnerWaves）

**职责**：按 Excel 配表（`LevelWave` 表）生成波次怪物。

**波次时间模型**：
```
timeStart（首怪延迟） → waveTimeContinue（刷怪窗） → 到点强制切下一波
                         ├─ intervalSpawn 间隔循环
                         └─ totalMonster 上限（可被窗截断）
```

**出生路线**：`lineSpawn` 字段控制 → 0 环绕玩家 / 1 上 / 2 下 / 3 左 / 4 右

**Boss 波标记**：`isBoss=1` → 清场 + Boss 入场特效 + BossBrain 激活

### 5.2 技能系统（PlayerSkills + SkillDefinitionBase）

**设计模式**：ScriptableObject 工厂模式，避免 `switch(skillId)`。

```
技能创建流程：
  PlayerSkills.GetDef(skillId)
    → SkillDefinitionBase.CreateRuntimeSkill(bindings)
      → CreateRuntimeSkillInternal(bindings)  // 子类实现，构造 ISkill
      → ApplyStatsToSkill(skill, level)        // 写入 per-level 数值

新增技能只需：
  1. 创建 *SkillDefinition.asset（SO）
  2. 实现 CreateRuntimeSkillInternal + ApplyStatsToSkill
  3. 在 SkillCatalog 中注册
```

**运行时绑定（SkillRuntimeBindings）**：
- `EnemyTag`：索敌 Tag
- `PlayerTransform`：玩家位置
- `CombatStatsProvider`：暴击/穿透/攻击系数查询
- `OnLineBeamVisual`：射线表现回调（LineRenderer）

**满级羁绊**：`bondedPassiveId` 字段 → 拥有该被动后技能才能升满 maxLevel。

### 5.3 Boss AI（BossBrain）

**设计目标**：所有 Boss 共用一个 `BossBrain` 组件和一个 Prefab，行为差异完全由 Excel 配表定义。

```
Monster 表 element[] 字段
  → BossBrain.BuildModules()
    → 按 type 创建模块实例（HomingKnife / Dash / BladeBurst / Zone / Clone / Summon / Resist / Revive）
    → 运行时按冷却轮流激活
```

**模块清单**：

| 模块 | 行为 |
|---|---|
| HomingKnife | 发射追踪弹 |
| Dash | 冲刺撞击 |
| BladeBurst | 360° 刀片爆发 |
| Zone | 持续伤害区域 |
| Clone | 召唤分身 |
| Summon | 召唤小怪 |
| Resist | 护盾抵抗 |
| Revive | 复活 |

### 5.4 索敌注册表（CombatTargetRegistry）

**问题**：`FindGameObjectsWithTag` 每帧全场景扫描，GC 压力大，同屏数百敌人时不可接受。

**方案**：静态注册表，按 Tag 维护活跃 `Transform` 列表。

```
EnemyBase.OnEnable()  → CombatTargetRegistry.Register("monster", transform)
EnemyBase.OnDisable() → CombatTargetRegistry.Unregister("monster", transform)
```

**查询 API**：
- `FindNearest(tag, from, maxRange)` → 最近敌人（O(n) 但 n=同屏敌人数，惰性剔除 null）
- `CountActive(tag)` → 存活计数（胜利判定）

### 5.5 对象池（GameObjectPool）

**借出登记模式**：`Get` 时记入 `LeasedObjects`（HashSet），`Release` 时移除。`ClearAllPools` 时只遍历池内对象与已借出集合，不做全场景扫描。

**SpawnLimiter**：控制同屏特效/弹丸上限，超限时拒绝生成而非无限堆积。

### 5.6 UI 弹窗框架（UIManager）

**架构**：单主栈（模态）+ 独立确认框 Overlay（弱 B）

```
┌─────────────────────────┐
│     Overlay Layer        │  ← UiConfirmDialog / UiToastPanel
│   (overlayRoot)          │     sortingOrder ≥ 800
├─────────────────────────┤
│     Stack Layer          │  ← 模态弹窗（后进先出）
│   (stackRoot)            │     sortingOrder: 200 + index
│   ┌─────────────────┐   │
│   │ Panel C (栈顶)    │   │
│   ├─────────────────┤   │
│   │ Panel B          │   │
│   ├─────────────────┤   │
│   │ Panel A (栈底)    │   │
│   └─────────────────┘   │
└─────────────────────────┘
```

**关键机制**：
- 同类型唯一实例（`Open<T>` 时若已有实例则抬到栈顶）
- `Time.timeScale` 引用计数暂停栈（`UiOpenOptions.PauseTime`）
- TMP 中文字体自动替换（`Open` 时对整棵 Panel 子树 `ApplyToHierarchy`）

### 5.7 事件系统（EventBus）

解耦模块间通信，典型事件：

| 事件 | 发布者 | 订阅者 |
|---|---|---|
| `EnemyDiedEvent` | EnemyBase | 结算统计 / 音效 / 能量掉落 |
| `PlayerDamagedEvent` | PlayerHealth | HUD 更新 / 伤害飘字 |
| `WaveTriggeredEvent` | SpawnerWaves | Boss 入场 / UI 提示 |
| `CardSelectionTriggeredEvent` | 能量系统 | RoguelikeCardPanel |

## 六、数据驱动架构

### 6.1 配表管线

```
Excel (.xls) → 导出工具 → FlatBuffers (.bytes) → Resources/Data/table_fb/
                                                        ↓
                                                  TableManager.LoadAll()
                                                        ↓
                                                  运行时字典查询
```

### 6.2 为什么用 FlatBuffers 而不是 JSON

FlatBuffers 的核心思路跟 JSON 一样——都是把数据存成文件供程序读取。区别在于格式：

| | JSON | FlatBuffers |
|---|---|---|
| 格式 | 纯文本 `{"HP":100}` | 二进制 `.bytes` |
| 读取过程 | 读文件 → 解析字符串 → 转数字 | 读文件 → 直接内存映射，跳过解析 |
| 包体大小 | 较大（文本冗余） | 较小 |
| 可读性 | 人可以直接打开看 | 二进制，不可读 |

**在本项目里的实际管线**：策划在 Excel 里填怪物/关卡/掉落数据 → 导出工具把 Excel 转成 FlatBuffers 二进制 `.bytes` → 放进 `Resources/Data/table_fb/` → 游戏启动时 `TableManager.LoadAll()` 一次性加载到内存 → 运行时通过 `TableManager.Get<T>(id)` 直接查，不需要等待 IO 或解析。

选择 FlatBuffers 而非 JSON 的两条理由：
1. **读取更快**：省了解析步骤，适合启动时批量加载 9 张表
2. **IL2CPP 裁剪友好**：FlatBuffers 生成的代码是强类型的类（如 `LevelWave`、`Monster`），IL2CPP 能准确判断需要保留哪些代码，不容易被裁掉

| `DropPool` | 掉落池概率配置 |
| `ShopTable` | 商店商品配置 |

### 6.5 IL2CPP 反射兼容

**什么是 IL2CPP？**

IL2CPP 是 Unity 的一套编译工具链，把 C# 代码先转成 C++，再编译为平台原生代码。对比 Unity 另一种方式 Mono：

| | Mono | IL2CPP |
|---|---|---|
| 执行方式 | C# → IL 中间码 → **JIT 即时编译**成机器码 | C# → IL → **转 C++** → **AOT 预编译**成机器码 |
| 包体积 | 较大（内置 JIT 运行时） | 较小（只包含实际用到的代码） |
| 代码裁剪 | 不裁 | **会移除未直接引用的代码**（Managed Stripping） |
| 适用平台 | 编辑器、旧版移动端 | **WebGL / iOS / 新版 Android** |

Unity WebGL 只能走 IL2CPP，没有 Mono 选项。这意味着微信小游戏天然受 IL2CPP 约束。

**代码裁剪带来的问题**

IL2CPP 在编译时做 **Managed Stripping**（代码裁剪），分析哪些代码被引用、哪些没有，没被直接引用的就删掉以减小包体。但反射调用（`GetMethod("__init").Invoke()`）是字符串形式的方法名，IL2CPP 的静态分析识别不了，会误判为"没人用"然后裁掉——运行时找不到方法就报错。

**本项目的修复**

FlatBuffers 原有的 `TableManager` 用反射来调每个表类型的 `__init` 方法。IL2CPP 裁掉了 `__init` → 数据加载失败。

修改方案：不走反射，直接通过接口调用：

```csharp
// ❌ 反射方案：IL2CPP 会裁掉 __init，运行时崩溃
var method = type.GetMethod("__init");
method.Invoke(obj, new object[] { 0, bb });

// ✅ 直接接口调用：IL2CPP 能看到 IFlatbufferObject.__init 被引用，不会裁
var obj = (IFlatbufferObject)Activator.CreateInstance(type);
obj.__init(0, bb);
```

关键点：**不是改了 IL2CPP 本身，是改了代码让它不被裁**。所有 FlatBuffers 表类型都实现了 `IFlatbufferObject` 接口，转型后直接调用 `__init`，IL2CPP 的静态分析能追踪到接口引用，不会误删。

## 七、微信小游戏适配

### 7.1 构建管线

```
Unity WebGL Build → webgl.wasm.framework.unityweb.js + wasmcode + data
                         ↓
              WXConvertCore 后处理
              ├─ ReplaceRules 正则替换（Emscripten API → 微信 runtime）
              ├─ Brotli 压缩（wasmcode + data-package）
              └─ 生成 game.js / game.json / project.config.json
                         ↓
              微信开发者工具 → 预览 / 上传审核
```

### 7.2 分包策略

| 分包 | 大小（br 压缩后） | 内容 |
|---|---|---|
| 首包 | ~650 KB | game.js + adapter + framework JS |
| wasmcode 分包 | 5.1 MB | WASM 引擎代码 |
| data-package 分包 | 17 MB | Unity 资源（字体 7MB + 场景 + 纹理 + 表数据） |

**关键配置**（`MiniGameConfig.asset`）：
- `ScriptOnly: 1` — WASM 代码分包
- `compressDataPackage: 1` — Brotli 首包压缩
- `assetLoadType: 1` — 首包放小游戏分包（无 CDN）
- `MemorySize: 256 MB` — WASM 堆预分配大小（Emscripten `TOTAL_MEMORY`，非微信平台限制）
- `Il2CppOptimizeSize: 1` — IL2CPP 体积优化

## 九、技术选型

| 选型 | 方案 | 理由 |
|---|---|---|
| 渲染 | Built-in 2D | 简单可靠，无 URP 在 WebGL 下的兼容风险 |
| UI | uGUI + TMP | Unity 原生方案，微信兼容性好 |
| 数据序列化 | FlatBuffers | 零拷贝读取，IL2CPP 兼容；Excel 导表成熟 |
| 热更新 | 不接入 | 微信小游戏审核快，全量更新可接受 |
| 资源管理 | Resources 文件夹 | 首包放分包策略下体积可控，无需 Addressables 复杂度 |
| 配色空间 | Gamma | Linear 在 2021 WebGL 有问题 |
| 字体 | msyh SDF（微软雅黑） | 覆盖 7000+ 常用汉字，微信环境可用 |
