### P1-5 经济系统改造：钻石 + 碎片分层

**现状问题**：金币是唯一通货，通关产出金币 → 商店买碎片 → 升星。一条线串到底，调任何一个数值全链条晃动。

**改造方案**：

```
首通 → 钻石 + 碎片（确定性，一次性）
重复刷 → 金币（日常消耗）
商店 → 钻石兑换碎片（限购，每日/每周刷新）
困难模式 → 额外碎片掉落（概率，吸引重复刷）
```

三条线独立可控：
| 产出线 | 通货 | 用途 | 调控手段 |
|--------|------|------|------|
| 首通 | 钻石 | 商店买碎片 | 每关给多少钻石 |
| 商店 | 碎片 | 升星 | 限购次数 + 价格 |
| 困难 | 碎片 | 补缺口 | 掉落概率 |

**具体改动**：
- [ ] `PlayerSaveData` 已有 `diamond` 字段，确认 `AddDiamond`/`SpendDiamond` 可用
- [ ] `BattleOutcomeCoordinator` 首通结算给钻石（首次通关 +N 钻石）
- [ ] `ShopTable` 新增钻石商品（PriceType=2），碎片只走钻石渠道
- [ ] 金币保留做日常消耗（可选：局内临时 buff、复活币），暂不强制

### P2-5 困难模式（复用地图，不增包）

**设计目标**：复用现有地图资源翻倍内容量，不增加包体。

**方案**：
| 项目 | 普通模式 | 困难模式 |
|------|---------|---------|
| 地图 | 现有 13 关 | 复用，不改 tile |
| 怪物配置 | 现有波次 | 不同波次组合（混合怪群 + 精英提前出场） |
| 数值 | 现有 | **不改血量/防御翻倍**，改怪物组合和 AI |
| 奖励 | 金币 + 首通钻石 | 困难专属碎片（掉落概率）+ 复活币 |
| 解锁条件 | 依次通关 | 普通模式通关本章后解锁 |

**核心原则**：
- 不做"血量×2"式的数值膨胀——那是页游套路
- 困难 = 不同的怪物组合，逼玩家换技能搭配
- 复活币作为困难专属掉落，商店买不到，区别于广告复活

- [ ] `ChapterLevelTable` 加 `difficulty` 字段（0=普通, 1=困难）
- [ ] `LevelWaveTable` 困难模式用独立波次配置（或 `waveGroupId`）

### 🔴 P0-性能：锁帧（30 分钟）

**根因**：[AppBootstrap.cs:26](Assets\Script\Game\App\AppBootstrap.cs#L26) `Application.targetFrameRate = 30` **在 WebGL 中完全无效**。Unity WebGL 忽略此设置，帧率由浏览器 requestAnimationFrame 控制。微信端正确做法是调用 SDK 封装的 `WX.SetPreferredFramesPerSecond()`。

代码库中 **从未调用** `WX.SetPreferredFramesPerSecond()`，SDK 已在 `WXBase.cs:1095` 封装好此接口。

**后果**：iOS 跑在 60~120fps → 37 个 Update() 每秒执行 3700+ 次 → CPU 飙到 77%。

**修复**：在 `AppBootstrap.Awake()` 中增加：

```csharp
#if UNITY_WEBGL && !UNITY_EDITOR
    WeChatWASM.WX.SetPreferredFramesPerSecond(30);
#endif
```

**预期效果**：CPU 降至 **12~25%**（降为 1/3~1/4），发热/耗电显著改善。FPS 从 100 降至 30。

> ⚠️ 锁帧后物理手感可能变化，需实测摇杆操作流畅度。如 30fps 感觉卡，折中到 45fps。

- [ ] `AppBootstrap.Awake()` 加 `WX.SetPreferredFramesPerSecond(30)`
- [ ] 出包 → 云测试验证 CPU 和 FPS 数据
- [ ] 如 30fps 操作体验差，调整到 45fps

### 🟠 P1-性能：内存峰值（1-2 小时）

**根因分析**：

| 嫌疑 | 说明 |
|------|------|
| 24 个 TileMap Prefab 全在 Resources | 即时不用也打进 data 分包，Unity 启动时可能预加载 |
| `Resources.UnloadUnusedAssets` 从未调用 | 切换场景后旧资源不释放 |
| 157 处 Instantiate/Destroy | 频繁分配导致堆碎片化，GC 不及时回收 |
| 8 个 mp3 全在 Resources | AudioClip 默认不解压但占用引用 |

**快速修复**：

- [ ] 闲置 TileMap（未配置关卡的 206/207/208/2041/401-409）移出 Resources → 同 P2-1，省 3-4MB 磁盘 + 若干运行时内存
- [ ] `GameResultPanel.OnOpen()` 结算后调 `Resources.UnloadUnusedAssets()`
- [ ] 场景切换（Home→Game→Home）时 `SceneManager.LoadSceneAsync` 后调一次 `Resources.UnloadUnusedAssets()`
- [ ] 检查 AudioService：确认音频是 Stream 模式加载而非 Decompress On Load

### 🟡 P1-性能：每帧运行时开销（持续）

- [ ] **37 个 Update()** — 锁帧后自然减负 70%，暂不逐一优化；先用 Profiler 定位 Top 5 热点
- [ ] **157 处 Instantiate/Destroy** — 确认对象池（GameObjectPool）覆盖了高频创建/销毁的物体（子弹、怪物碎片、VFX）
- [ ] **92 处 FindObjectOfType/GetComponent** — 大部分在 Awake/Start 里不是问题；但 `EnemyBase.cs`（7处）、`BattleOutcomeCoordinator.cs`（9处）、`DamageFloatTextPresenter.cs`（6处）需排查是否有 Update 内调用
- [ ] `FindObjectsOfType<PlayerSkills>()` 在 [GameResultPanel.cs:404](Assets\Script\Game\UI\Result\GameResultPanel.cs#L404) — 结算面板只需调一次，可缓存
