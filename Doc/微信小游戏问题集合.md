# 微信小游戏问题集合

---

## 1. 存储类 Bridge 函数 stub 导致 WXUncaughtException 崩溃

**日期**: 2026-05-20

**现象**: 微信开发者工具中点击"开始游戏"后崩溃，报错：
```
plugin.js:5 missing function: WXStorageGetStringSync(env: Windows,mg,...)
Error: WXUncaughtException
abort() at webgl.wasm.framework.unityweb.js
```

**触发路径**:
```
点击"开始游戏"
  → LoginSceneController.OnStartGameClicked
    → PlayerProfileService.LoadOrCreate()
      → PlayerPrefs.GetString(key, defaultValue)
        → WXSDKManagerHandler.StorageGetStringSync (C#)
          → _WXStorageGetStringSync (JS bridge)
            → abort()  ← 崩溃
```

**根因**: `webgl.wasm.framework.unityweb.js` 中 9 个 `_WXStorage*` bridge 函数均为 Emscripten 生成的 stub 占位实现，直接调用 `abort(-1)`：

```javascript
function _WXStorageGetStringSync() {
    err("missing function: WXStorageGetStringSync");
    abort(-1);
}
```

而其他已正常工作的 bridge 函数（如 TCPSocket、Touch 事件）直接调用 `window.WXWASMSDK.*`。WeChat SDK 的 JS 侧（`storage.js`）实际有正确的存储实现，但 Emscripten 桥接层从未连通。

**涉及的 9 个 stub 函数**:
- `_WXStorageDeleteAllSync`
- `_WXStorageDeleteKeySync`
- `_WXStorageGetFloatSync`
- `_WXStorageGetIntSync`
- `_WXStorageGetStringSync`
- `_WXStorageHasKeySync`
- `_WXStorageSetFloatSync`
- `_WXStorageSetIntSync`
- `_WXStorageSetStringSync`

**修复方案**:

将 stub 改为直接调用 `window.WXWASMSDK.WXStorage*`，按 IL2CPP Emscripten 调用约定处理参数编组：
- `char*` 参数用 `UTF8ToString()` 转 JS string
- string 返回值通过 `_malloc` + `stringToUTF8` 分配 WASM 内存后返回指针
- bool 返回值转 0/1

**修改文件**:

1. **永久修复** — `Assets/WX-WASM-SDK-V2/Editor/WXConvertCore.cs`
   - 新增 `FixWXStorageStubs(ref string text)` 方法，每次构建时自动替换 stub
   - 在框架 JS 转换流程（`adapt framework`）中调用

2. **构建产物** — `Build/minigame/minigame/webgl.wasm.framework.unityweb.js`
   - 手动替换 9 个 storage stub 函数为真实实现

**关联代码**: `Assets/Script/Game/PlayerData/Services/PlayerProfileService.cs`, `Assets/Script/Game/PlayerData/Storage/PlayerPrefsSaveStorage.cs`
