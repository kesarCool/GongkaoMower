# 局外养成系统设计方案

日期: 2026-06-03

---

## 一、整体架构

```
局外（Home 场景）
  ├─ 英雄升级（金币消费，提升基础属性）
  ├─ 英雄升阶（等级里程碑，解锁附带技能）
  ├─ 背包/碎片（收集兑换英雄）
  └─ 货币（金币/钻石，关卡产出 + 任务奖励）

局内（Game 场景）
  └─ 属性由 CharacterAttributes(SO) + UpgradeData(Save) 叠加计算
```

## 二、FlatBuffer 分析

### 2.1 数据量估算

| 维度 | 数量 |
|------|------|
| 英雄数 | 5（当前）→ 10（目标） |
| 升级等级 | 20 级（可先做 10 级） |
| 升阶 | 3 阶（普/稀有/传说） |
| 属性字段 | 8（attack/maxHp/defense/moveSpeed/crit/critRate/pierceCount/pierceRate） |

数据总量 = 10 × (20 + 3) × 8 ≈ 1840 个浮点数。

### 2.2 对比

| 维度 | FlatBuffer | ScriptableObject |
|------|-----------|------------------|
| 数据量 | 适配千行级 | 适配百行级 |
| 编辑 | Excel → 导出，间接 | Inspector 直改，即时 |
| 公式计算 | Excel 内写公式自动算 | 手填或写 Editor 工具 |
| 策划友好度 | 高（Excel 批量操作） | 低（逐条点 Inspector） |
| 维护成本 | 中（需维护导出管道） | 低（SO 文件直接存） |
| 当前项目先例 | LexiconTable/LevelWave/Monster | CharacterDefinition/SkillDef |

### 2.3 结论

**不需要 FlatBuffer**。理由：

1. 数据量小（<2000 行），ScriptableObject 完全够用
2. 升级曲线可以用代码公式生成，不需要 Excel —— `Mathf.Lerp(start, end, level/maxLevel)` 一条线搞定
3. 当前项目已经有 CharacterAttributes SO 模式，加升级数据是同一套，不引入新工具链
4. 如果未来英雄数量飙升（50+），再切 FlatBuffer 也不迟——数据模型和交互面已定，迁移成本低

**方案**：新建 `HeroUpgradeData` ScriptableObject，每个英雄一个 `.asset`，包含 per-level 的 `goldCost` 和 `attributeMultiplier`（乘算到基础属性上）。

## 三、英雄升级系统

### 3.1 数据模型

```csharp
// 新建
[CreateAssetMenu(menuName = "Game/Hero Upgrade Data")]
public class HeroUpgradeData : ScriptableObject
{
    public string characterId;
    public int maxLevel = 20;
    public int[] goldCostByLevel;       // 升到 Lv.N 的金币消耗
    public float[] attributeScaleByLevel; // Lv.N 的属性乘算系数（1.0→3.0）
}
```

### 3.2 升级公式

```
最终属性 = CharacterAttributes.attributes × UpgradeScale + 被动加成
          ↑ SO 配置（固定）      ↑ 升级乘算        ↑ 局内被动技能
```

### 3.3 存档扩展

```csharp
// PlayerSaveData 新增
public int gold;                           // 金币
public int diamond;                         // 钻石（预留）
public HeroUpgradeEntry[] heroUpgrades;     // 每个英雄的升级数据

[Serializable]
public class HeroUpgradeEntry
{
    public string characterId;
    public int level;      // 1-20
    public int stage;      // 0=普通, 1=稀有, 2=传说
}
```

### 3.4 金币来源

通过 `ChapterLevel` 表 `rewardItemIds` 字段配置关卡产出。首次通关和重复通关可以配不同奖励（`firstRewardItemIds` + `rewardItemIds`）。

### 3.5 升级消耗曲线（示例）

| Lv | 升级到该级消耗 | 累计消耗 | 属性倍率 |
|----|-------------|---------|---------|
| 1 | 0 | 0 | 1.0× |
| 2 | 200 | 200 | 1.1× |
| 3 | 350 | 550 | 1.2× |
| ... | ... | ... | ... |
| 10 | 3000 | 12,000 | 2.0× |
| 20 | 15,000 | 80,000 | 3.0× |

## 四、升阶系统

### 4.1 升阶规则

| 阶 | 条件 | 效果 |
|----|------|------|
| 普通 | 默认 | 无额外 |
| 稀有 | Lv.10 + 消耗碎片×20 | 解锁一个"阶位技能"（如攻击+10% 光环） |
| 传说 | Lv.20 + 消耗碎片×50 | 解锁第二个阶位技能（如击杀回复血量） |

### 4.2 阶位技能

阶位技能是**局外解锁、局内常驻**的被动效果，不占局内被动槽位。

```csharp
// CharacterDefinition 新增字段
public SkillId[] stageSkills;  // [稀有技能, 传说技能]
```

CharacterConfigApplier 读取 `heroUpgrade.stage >= 1` → 自动装填 `stageSkills[0]`。

## 六、物品系统

### 6.1 统一物品表（Excel → FlatBuffer）

沿用现有 `.xls → flatc → .cs + .bytes` 管线。Excel 文件放在 `../client/Share/table/xls/ItemTable_c.xls`。

**Excel 列定义：**

| Row 1 | required | required | optional | required | required |
|--------|----------|----------|----------|----------|----------|
| Row 2 | sint32 | string | string | sint32 | string |
| Row 3 | ID | ItemName | Icon | Grade | Description |

**字段说明：**

| 字段 | 类型 | 说明 |
|------|------|------|
| ID | sint32 | 主键，≥1 |
| ItemName | string | 物品名（如"金币""奋斗哥碎片"） |
| Icon | string | 图标资源路径（如 `UI/Items/icon_gold`） |
| Grade | sint32 | 品级：0=白 1=绿 2=蓝 3=紫 4=金 |
| Description | string | 描述文本 |

**操作步骤：**

1. 创建 Excel 文件 `ItemTable_c.xls`（首 Sheet 名 `ItemTable`）
2. `[TM工具集]/xls转cs` → 自动生成 `ProtoTable/ItemTable.cs` + `table_fb/ItemTable.bytes`
3. `TableManager.mTypeList` 已注册 `typeof(ItemTable)`（本章修改）
4. 运行时通过 `TableManager.Instance.GetTable<ItemTable>()` 读取，按 ID 查字典

物品 ID 规划：

| ID 范围 | 用途 |
|---------|------|
| 1-99 | 货币（1=金币, 2=钻石） |
| 100-199 | 英雄碎片（100+角色索引） |
| 200-299 | 消耗品（宝箱钥匙等） |
| 300+ | 武器（后续） |

### 6.2 统一 ItemCell

一个预制体适配所有物品展示：

```
ItemCell (Prefab)
  ├─ iconImage (Image)
  ├─ nameText (TMP)
  ├─ countText (TMP, 数量角标)
  └─ gradeBorder (Image, 品级边框颜色)
```

`Bind(Sprite icon, string name, int count, int grade)` — 传入参数即可，不区分物品类型。

### 6.3 关卡产出

在 `ChapterLevel` 表中配置奖励：

```
ChapterLevel 表新增字段：
  rewardItemIds   int[]   // [1, 101, 101] = 金币+2片碎片
  rewardItemCounts int[]  // [200, 3, 5]
```

胜利结算时读取 `rewardItemIds/counts` → 写入存档 + 在结算面板用 `ItemCell` 展示每个物品。

### 6.4 存档存储

```csharp
// PlayerSaveData v4
public int[] itemIds;      // 持有物品 ID
public int[] itemCounts;   // 对应数量
```

同步写在 `PlayerProfileService` 中提供 `AddItem(int id, int count)` / `GetItemCount(int id)` 方法。

## 七、坑点与风险

| # | 坑点 | 严重度 | 应对 |
|---|------|--------|------|
| 1 | 升级 + 被动叠加线性失控 | 高 | 总效果 = base × (1 + upgrade%) × (1 + passive%)，设硬上限 |
| 2 | 金币产出太少→升级无感；太多→瞬间满级 | 中 | 先用公式拟合，快速调参 |
| 3 | PlayerSaveData 版本兼容 | 中 | v4 默认值兜底，`gold=0` 不崩溃 |
| 4 | 阶位技能与局内被动槽位概念混淆 | 低 | UI 上区分"阶位"和"被动"两栏 |
| 5 | 碎片数膨胀→玩家等待感强 | 中 | 首通奖励一次性补足，日常为补充 |
| 6 | `HeroUpgradeData` per-hero SO 数量膨胀 | 低 | 10 个 `*.asset` 文件可控 |
