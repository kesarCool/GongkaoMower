ShopTable 已生成 17 个字段，本次用到的：

| 字段 | 类型 | 用途 | 示例 |
|---|---|---|---|
| `ID` | int | 行 ID | 1001 |
| `ShopName` | string | 商品显示名 | "奋斗哥碎片" |
| `ShopType` | enum | 商店类型 | normal=日常商店 |
| `LatticeName` | string | 货架格子标签 | "每日" |
| `ItemID` | int | 直售物品 ID | 0=走 DropID |
| `ItemNumber` | int | 单次购买数量 | 5 |
| `DropID` | int | 掉落池 ID（随机奖励） | 0=直售 |
| `PriceType` | int | 货币类型 | 1=金币, 2=钻石 |
| `OldPrice` | int | 原价（划线展示） | 2000 |
| `PurchaseDiscount` | int | 折扣百分比 | 80（=8折） |
| `PurchaseNum` | int | 每周期限购次数 | 3 |
| `Refresh` | int | 刷新周期 | 1=每日, 2=每周, 0=不刷新 |
| `Unlock` | int | 解锁关卡 ID | 301（通关后解锁） |
| `Hide` | int | 隐藏条件 | 0=显示, 1=永久隐藏 |

**关于价格**：当前价格用 `OldPrice * PurchaseDiscount / 100` 计算实际售价。例如原价 2000，折扣 80 → 实价 1600 金币。

## 五、限购与刷新机制

### 5.1 存储结构

```csharp
[Serializable]
public class ShopPurchaseLog
{
    public int shopItemId;       // ShopTable.ID
    public int purchasedCount;   // 本周期已购买次数
    public long lastResetTimestamp; // 上次重置时间戳
}
```

每次购买时 `purchasedCount++`。刷新时 `purchasedCount = 0`。

### 5.2 刷新规则

| Refresh 值 | 含义 | 重置时机 |
|---|---|---|
| 0 | 不刷新（一次性） | 永不重置 |
| 1 | 每日刷新 | 跨自然日（本地时间 00:00） |
| 2 | 每周刷新 | 跨自然周（周一 00:00） |

每次打开商店时检查是否跨周期，是则全量重置该 Refresh 类型的限购计数。

### 5.3 生命周期商品

`Refresh = 0` 且 `PurchaseNum > 0` → 终身限购 N 次，买完后该格永久灰显/售罄。

## 六、解锁条件

`Unlock` 字段存储关卡 ID：
- `0`：无限制，始终开放
- `> 0`：需通关该关卡后才显示该商品

复用现有 `PlayerProfileService.HasCleared(levelId)` 判断。

---

## 七、购买流程

```
玩家点击商品
  → 已售罄？ → Toast "已售罄"
  → 金币不足？ → Toast "金币不足"
  → 弹出确认弹窗 "XX碎片 ×5，消耗 1600 金币"
    → 确认
      → SpendGold(price)
      → AddItem(itemId) 或 AddFragments(charId)
      → RecordShopPurchase(shopId)
      → 刷新 UI
```
