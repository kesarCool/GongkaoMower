## 二、问题分级与优化方案

### P0 🔴 严重阻塞

#### 2.1 wx.request 失败率 100%（分数 0）

- **影响**：全部 46 台设备，所有网络请求失败
- **根因**：服务器域名未在微信公众平台配置白名单
- **修复**：登录 [微信公众平台](https://mp.weixin.qq.com) → 开发管理 → 开发设置 → 服务器域名 → 添加 `request` 合法域名。**纯配置问题，不需要改代码。**

#### 2.2 黑屏 0.7%（iPhone XS Max iOS 18.7.6）

- **根因**：低端 iOS 内存不足（iPhone XS Max 仅 4GB RAM），内存峰值 941MB 时可能触发系统杀进程或 GPU 资源回收失败
- **修复**：降低内存峰值（见 3.4），低端设备降级渲染质量

---

### P1 🟠 性能瓶颈

#### 2.3 首资源包下载慢（avg 5273ms，最高 16898ms）

- **根因**：data-package 16MB（Br 压缩），首资源包未开启 CDN 压缩或包体过大
- **优化**：
  1. **纹理压缩**（省 ~1.7MB）：`login_bg.png`(498K)、`pic_sl.png`(206K) 等 UI 大图改用 Crunched ETC2，Max Size=1024，Quality=50
  2. **删除 unused 纹理**（省 ~400KB）：`Assets/Res/Effect/_Effect/` 下噪音纹理若未引用就删除
  3. **转换面板勾选"压缩首资源包"**：WX SDK → 导出设置 → 勾选压缩选项，开启 CDN gzip/br
  4. **字体 Atlas 已最优**：2048×2048 Alpha8 → Br ~1.8MB，不需要再动

#### 2.4 WASM 编译慢（avg 843ms，低端机最高 3899ms）

- **根因**：wasmcode 5.4MB，中低端 Android 编译慢
- **优化**：
  1. `PlayerSettings.SetManagedStrippingLevel` 从 Medium 提到 High
  2. 使用 WX SDK 的**代码分包工具**（WasmSplit）分离插件代码
  3. 剔除不用的 Unity 模块（Physics、Analytics 等）——PlayerSettings → Strip Engine Code

#### 2.5 CALLMAIN 耗时高（avg 1308ms，iOS 最高 3141ms）

- **根因**：主线程初始化逻辑繁重，`BattleLoadingSceneController.Start()` 在首场景同步执行较多操作
- **优化**：
  1. 首场景（BattleLoading）精简物件：当前 `EnsureMinimalUi()` 动态建 UI，OK；但不必要的 Prefab/组件应该延迟到 Game 场景再加载
  2. `TableManager.Init()` 在 BattleLoading 同步执行——如果 FB 表数据量大，考虑异步分帧加载
  3. `AudioService.LoadGroupAsync` 已在用协程，OK
  4. `BattleChineseFontRuntime.EnsureLoaded()` — Resources.Load 4MB SDF 字体可能是首帧阻塞点，建议移到 Boot 场景预加载

#### 2.6 CPU 均值过高（分数 37，严重不达标）

- **根因**：主循环 Update 开销大 + 未限制帧率
- **优化**：
  1. **限制帧率**：`Application.targetFrameRate = 30`（休闲割草游戏 30fps 完全够用）
  2. **减少 Update 开销**：
     - `PlayerController.Update()` 每帧调 `FindObjectOfType<DynamicJoystick>()`（等 _joystick 缓存未初始化时）
     - `SpawnerWaves` 每帧跑 `NormalLoop` 协程
     - `CombatTargetRegistry` 已优化（O(1) 查询），OK
  3. **对象池已在使用**：Bullet、Enemy、EnergyPickup 已走 GameObjectPool，OK
  4. **Unity Profiler 查热点**：打包 Development Build → 连接 Profiler → 看 CPU Usage 里的 Update 调用栈

#### 2.7 内存峰值过高（最高 1531MB，OPPO Find X8）

- **根因**：纹理未压缩、字体 Atlas 4MB、场景资产堆积
- **优化**：
  1. **纹理压缩**（见 2.3）— 4MB raw → ~1MB ASTC 6×6，GPU 内存暴降
  2. **转换面板合理设置 UnityHeap 预留内存**：WX SDK → 导出设置 → UnityHeap 建议 256-384MB
  3. **AssetBundle 未用**——你目前全走 Resources，意味着**所有资源常驻内存**。后续大资源多时考虑按关卡分包加载
  4. **字体 Atlas**：4MB Alpha8 → 如果用 ASTC 4×4 压缩可降到 ~1MB，但可能影响 SDF 质量。**建议不动，1.8MB Br 已经够小**
  5. **场景切换时清理**：`GameObjectPool.ClearAllPools()` 已在 `GameResultPanel.OnOpen()` 调用，OK
  6. **当前最大内存占用疑点**：`Resources/Map/TileMap101.prefab` + `TileMap102.prefab` 两个地图 Prefab。检查地图 Prefab 是否包含大量 Tile 贴图、是否有未合并的 Tilemap

### P2 🟡 体验优化

#### 2.8 轻微卡顿（iPhone 15 Pro 0.8%、iPhone 13 Pro 1.0%）

- **优化**：限制帧率到 30 → 减少 GPU 负载 → 卡顿自然消失。设置 `QualitySettings.vSyncCount = 0`

#### 2.9 iPhone 13 Pro FPS 51

- **优化**：设 `Application.targetFrameRate = 60`（保留高端机 60fps），低端机 `targetFrameRate = 30`

## 三、优化执行顺序（按收益/成本）

| 优先级 | 优化项 | 预期收益 | 改代码量 |
|--------|--------|---------|---------|
| P0-1 | 微信后台配置 request 域名 | 修复 100% 网络失败 | 无 |
| P1-1 | `Application.targetFrameRate = 30` | CPU 分数 37→70+ | 1 行 |
| P1-2 | 纹理压缩（UI 大图 + unused 纹理） | 包体 -1.7MB, 内存 -50MB+ | 无（Unity Inspector） |
| P1-3 | ManagedStrippingLevel → High | wasmcode -0.5~1MB | 1 行 |
| P1-4 | 首资源包压缩（WX SDK 勾选） | 下载时间 -30% | 无（SDK 配置） |
| P1-5 | BattleLoading 延迟非关键初始化 | CALLMAIN -30% | 少量 |
| P1-6 | 地图 Tilemap 检查 + 合并 | 内存 -50~200MB | 少量 |
| P2-1 | `QualitySettings.vSyncCount = 0` | 卡顿 -50% | 1 行 |
