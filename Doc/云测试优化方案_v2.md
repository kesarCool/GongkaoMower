## 二、根因分析

### 2.1 30fps 为何没效果甚至反效果

`targetFrameRate = 30` 在 `AppBootstrap.Awake()` 设置，但两个问题：

**A) WX SDK 可能覆盖了 targetFrameRate**

微信小游戏导出时 WX SDK 会设置自己的帧率控制。`WXConvertCore` 或 `game.js` 模板里可能调了 `UnityApplication.targetFrameRate = 60`。AppBootstrap 的设置在 WebGL export 后被覆盖。

**B) iOS requestAnimationFrame 行为**

WebGL 下的帧率由浏览器的 `requestAnimationFrame` 驱动。iOS Safari/WKWebView 的 rAF 固定约 60fps，即使 Unity 设定 30，浏览器仍在 60Hz 刷新。如果 Unity 每秒只渲染 30 帧但浏览器刷 60 次，会导致渲染不一致和额外开销。

**验证方法（下次构建前）**：在 `BattleLoadingSceneController.Start()` 加一行：
```csharp
Debug.Log($"[FPS] targetFrameRate={Application.targetFrameRate} vSync={QualitySettings.vSyncCount}");
```
看打包后实际输出的值。

### 2.2 CPU 得分为何降到 29

iOS 设备 CPU 占用严重超标：
- iPhone 8 Plus: **123.4%**（多核满载+）
- iPhone 13 Pro: **87.4%**
- iPhone 15 Pro: **超 40%**

推测主因：

**A) `QualitySettings.vSyncCount = 0` 让浏览器无限制刷新**

vSync=0 在移动端 WebGL 不是"关垂直同步"，而是让渲染循环不等待屏幕刷新。这导致 Unity 尽可能快地提交帧（即使帧内容没变），CPU 和 GPU 空转。

**B) Physics2D 查询开销**

`SkillLineBeam2D.Tick()` 每发一束射线就调用 `Physics2D.RaycastAll()`。3 条射线 × 每帧 = 3 次全场景射线检测。`SkillAutoProjectile` 等其他技能也在做 FindNearest 查询。`CombatTargetRegistry.FindNearest` 虽然 O(1)，但被多个技能每帧同时调用。

**C) 怪物量大时 Update 堆积**

SpawnLimiter 允许 100 只怪在场。每只怪有 `EnemyBase.Update()`（移动逻辑），加上 `EnemyWordLabel` 的 TMP 文字更新。100 只 × Update = 每帧 100 次逻辑调用。

### 2.3 卡顿率恶化（最高 3.7%）

直接由 CPU 过载导致——CPU 跟不上渲染节奏 → 丢帧 → 卡顿率上升。iPhone 13 Pro FPS 从 51 降到 45 也是同因。

## 三、优化方案（按优先级）

### P0：修复 vSync + targetFrameRate 设置

**推测 vSyncCount=0 在 WebGL 上起反作用。改为：**

```csharp
// AppBootstrap.Awake() 修改为：
QualitySettings.vSyncCount = 1;        // WebGL 下设为 1 让浏览器控制
Application.targetFrameRate = 30;       // 保留
Time.fixedDeltaTime = 1f / 30f;         // 保留
Time.maximumDeltaTime = 1f / 15f;       // 新增：防止单帧耗时过长
```

如果 vSyncCount=1 后帧率锁不住 30，改为：
```csharp
QualitySettings.vSyncCount = 0;
Application.targetFrameRate = 30;
// 去掉 vSync=0 与 targetFrameRate 同时设置——二者在 WebGL 下冲突
```

### P1：减少 Physics2D 射线检测开销

**`SkillLineBeam2D.Tick()` 每次发射对所有射线做 `RaycastAll()`：**

```csharp
// 当前：每条射线一次 RaycastAll，3 条 = 3 次场景遍历
// 优化：合并为一次 CircleCast 或 OverlapArea，或用 NonAlloc 版本减少 GC
RaycastHit2D[] hits = Physics2D.RaycastAll(origin, d, beamLength, hitMask);

// 改为 RaycastNonAlloc 避免每次分配数组：
private static readonly RaycastHit2D[] _sharedHits = new RaycastHit2D[32];
int hitCount = Physics2D.RaycastNonAlloc(origin, d, _sharedHits, beamLength, hitMask);
for (int h = 0; h < hitCount; h++) { ... }
```

对其他使用 `RaycastAll` 的技能（`SkillAutoProjectile`、`SkillOrbBladeHit`）同样改为 NonAlloc。

### P2：降低 SpawnLimiter 上限

当前配置允许 **100 只怪 + 100 颗子弹** 同时在场。实测不需要这么多：

| 键 | 当前 maxAlive | 建议 |
|----|-------------|------|
| Enemy | 100 | **60** |
| Bullet | 100 | **50** |
| EnergyPickup | 50 | 50（不变） |

修改 `SpawnLimiter.prefab` 的 Inspector 值即可。

### P3：PlayerController.Update 减少 FindObjectOfType

当前 `MoveToTarget()` 每帧调 `FindObjectOfType<DynamicJoystick>()`（未缓存时）。在循环中缓存：

```csharp
// 在 Awake 中缓存
_joystick = FindObjectOfType<DynamicJoystick>();

// MoveToTarget 中移除懒惰查找
```

### P4：WX SDK 勾选压缩首资源包

上次提了但不确定是否已做。配置入口：微信小游戏 → 转换小游戏 → 导出设置 → 勾选"压缩首资源包"。

## 四、预期效果

| 优化项 | 影响指标 | 预期 |
|--------|---------|------|
| vSync=1 + targetFrameRate 修复 | CPU | 29 → 50+ |
| Physics2D NonAlloc | CPU + 卡顿率 | GC 减少，卡顿率 3.7% → <1% |
| SpawnLimiter 降上限 | CPU + 内存 | 降低 Update 累积 |
| FindObjectOfType 缓存 | CPU（微） | 每帧省一个 FindObject 调用 |
| 首资源包压缩 | 下载时间 | 5197ms → ~3500ms |

---

## 五、建议下次云测试前

1. 先做 **P0**（只改 3 行），重新构建，验证 CPU 分数是否回升
2. 如果 P0 效果不明显，再加 **P1**（Physics2D NonAlloc）和 **P3**（FindObjectOfType 缓存）
3. P2（SpawnLimiter）是 Inspector 手工调整，可同步做
