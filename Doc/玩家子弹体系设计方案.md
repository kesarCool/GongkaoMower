# 玩家子弹体系设计方案

## 一、现状

```
PlayerBullet (只有一个)
  └─ Bullet.cs : transform.position 移动, 单次碰撞 → 消失
      ├─ SkillAutoProjectile 发射（自动索敌子弹）
      └─ PlayerController.AutoShoot 发射（旧版）
```

Boss 侧已经有完整分层：

```
BossBullet (abstract)
  ├─ HomingBullet : 追踪弹（转向 + Launch 统一入口）
  └─ StraightBullet : 直飞弹（沿初始方向，不追踪）
```

**玩家侧没有基类，Bullet.cs 是唯一实现。所有技能共用一个 Bullet，靠参数凑合区分。**

## 二、未来技能子弹类型

| 子弹类型 | 行为 | 对应技能 |
|----------|------|----------|
| 普通弹 | 直线飞行，撞怪消失 | 弹无虚发 |
| 穿透弹 | 直线飞行，穿透 N 个怪后消失 | 气贯长虹 |
| 反弹弹 | 直线飞行，撞墙反弹 N 次 | 飞镖 |
| 弧形弹 | 曲线/抛物线飞行 | 石破天惊（已有 GrenadeProjectile） |
| 剑气 | 宽体直线飞行，穿透全部怪 | 剑气纵横 |

## 三、分层设计

```
PlayerBullet (abstract)     ← 玩家子弹基类（新建）
  ├─ StraightBullet         ← 普通直飞弹（替代现有 Bullet.cs）
  ├─ PiercingBullet         ← 穿透弹：每怪扣 1 穿透次数
  ├─ BouncingBullet         ← 反弹弹：撞墙反射 N 次
  └─ BeamBullet             ← 宽体剑气：持续飞行，全穿

与 BossBullet 的区别：
  BossBullet : 打 Player，不统计伤害，没有技能来源
  PlayerBullet : 打 monster，统计 BattleRunMetrics，有 SkillId
```

### 基类属性

```
PlayerBullet（abstract, 继承 MonoBehaviour）
  ├─ speed / damage / lifetime          ← 通用
  ├─ skillSource : SkillId               ← 技能来源（统计用）
  ├─ wallMask : LayerMask                ← 撞墙检测层
  ├─ Launch(dir, speed, dmg, life)       ← 统一发射入口（与 Boss 一致）
  └─ abstract void OnFrameMove()         ← 每帧移动（子类不同）
```

### 各子类差异

| 子类 | OnFrameMove | 额外属性 | 碰撞行为 |
|------|-----------|---------|---------|
| StraightBullet | `transform.position += dir * speed * dt` | 无 | 撞怪消失 |
| PiercingBullet | 同 Straight | `pierceCount` | 撞怪扣 pierceCount，归零消失 |
| BouncingBullet | 同 Straight | `bounceCount` | 撞墙反射 `Vector2.Reflect`，归零消失 |
| BeamBullet | 同 Straight | `beamWidth` | 全穿透，lifetime 到期消失 |

## 四、与 Boss 体系的对比

| 维度 | PlayerBullet | BossBullet |
|------|-------------|------------|
| 目标 | monster 标签 | Player 标签 |
| 伤害统计 | BattleRunMetrics | 无 |
| 技能来源 | SkillId | EnemyBase.ContactDamage |
| 基类类型 | abstract class + MonoBehaviour | abstract class + MonoBehaviour |
| Launch 签名 | `Launch(dir, speed, dmg, lifetime, skillId)` | `Launch(dir, speed, dmg, lifetime)` |
| 共用能力 | 直线飞行、墙检测 | 追踪、直线飞行 |

**两个基类独立存在，不互相继承**——打击对象不同、统计需求不同、扩展方向不同。

## 五、迁移路径

### 第一步：创建 PlayerBullet 基类

```
PlayerBullet 基类
  ├─ 字段：speed, damage, lifetime, skillSource, wallMask
  ├─ Launch(Vector2 dir, float speed, float dmg, float life, SkillId source)
  ├─ virtual OnFrameMove() = transform.position += dir * speed * dt
  └─ 碰撞：OnTriggerEnter2D → 对 monster 造成伤害 + 统计 + 释放
```

### 第二步：重构现有 Bullet.cs → StraightBullet

Bullet.cs 的功能就是"直飞 + 单次碰怪消失"，被 StraightBullet 完全覆盖。重构步骤：
1. 新建 `PlayerStraightBullet.cs` 继承 PlayerBullet
2. 旧 `Bullet.cs` 保留，标记 `[Obsolete]`
3. `SkillAutoProjectile` 的 bulletPrefab 切到新 Prefab
4. `PlayerController.AutoShoot` 的 bulletPrefab 切到新 Prefab

### 第三步：后续按需加子类

- 气贯长虹（LineBeam）→ 新值 `PiercingBullet`
- 飞镖（新技能）→ 新值 `BouncingBullet`
- 剑气（新技能）→ 新值 `BeamBullet`

## 六、关键设计决策

### Q1：PlayerBullet 要不要继承自 BossBullet？
**不要。** 即使共享 speed/damage/lifetime 这些字段，两个体系的目标标签、伤害统计、技能来源完全不同。硬继承会导致 `targetTag` 和 `skillSource` 的语义混乱，子类要大量 override，不如各自独立。

### Q2：要不要把现有 Bullet 的方法全部保留到基类？
**不。** 现有 Bullet 的 `SetDirection` + `ApplySkillShot` 两步调用，不如一个统一的 `Launch(dir, speed, dmg, lifetime, skillId)` 入口。BossBullet 已经验证了单入口模式更清晰。

### Q3：弧形弹/手榴弹要不要进这套体系？
**不进。** `GrenadeProjectile` 已经有自己独立的物理模拟（抛物线 + 落地 AOE），和直线弹体系差异太大。强行纳入只会让基类肿胀。保持独立。

### Q4：穿透弹撞墙怎么办？
撞墙也算穿透次数消耗——墙也算"碰了一次"，归零消失。
