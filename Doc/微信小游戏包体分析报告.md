## 二、包体构成分析

### data-package 真实构成（16MB Br）

| 成分 | Br 压缩后 | 占比 |
|------|----------|------|
| Unity 内置（Shader / 默认贴图 / Unity 运行时） | ~3-4MB | ~22% |
| 场景资产（UI 贴图 / Prefab / SO） | ~6-8MB | ~44% |
| 字体 Atlas（2048×2048 Alpha8） | ~1.8MB | 11% |
| IL2CPP metadata | ~1-2MB | ~10% |
| 音效（11 个文件，464KB raw） | ~0.3MB | 2% |
| 表数据（FlatBuffer .bytes） | ~1MB | 6% |
| 角色模块 SO（32KB，可忽略） | <0.1MB | <1% |

最大优化空间：**场景资产（贴图压缩 + 删未用纹理）** 和 **UI 纹理未开压缩**。

### 主包构成（~1.2MB）

| 成分 | 大小 |
|------|------|
| game.js（WX SDK 模板） | ~200KB |
| framework.js（Unity WebGL 桥） | ~400KB |
| plugins（WX SDK 插件 JS） | ~300KB |
| game.json + project.config.json | <10KB |
| 首次启动图 / 开放数据域 | ~200KB |

### wasmcode 分包（5.4MB）

IL2CPP C++ → WASM 编译产物。不可手动优化，依赖 Unity 的 Managed Stripping Level 和代码量。当前 Medium stripping，5.4MB 属于正常范围。

## 三、音频：已解决，状态稳定

### 路径方案（最终态）

音频统一放在 `Assets/Resources/Audio/`，Unity 自动打进 data-package。加载方式：`Resources.Load<AudioClip>()`，绕过微信 InnerAudioContext 和 CDN 下载。

### 格式兼容性

| 格式 | 已有文件 | 微信 WebGL 支持 |
|------|---------|----------------|
| mp3 | 5 个 | ✅ |
| wav | 3 个 | ✅ |
| ogg | 2 个（enemy_die, field_generator） | ⚠️ 部分安卓不支持 |

**建议**：2 个 ogg 文件转 mp3，避免兼容问题。不影响包体。

### Editor 下音效验证

音频同时在 `Resources/Audio/` 和可能残留的 `Res/Audio/`。Editor Play 时走 `Resources.Load`，需确认 `Assets/Resources/Audio/` 已覆盖全部音频文件。

## 五、构建问题

### 5.1 分包加载失败（2026-05-31 新增）

```
loadSubpackage:fail module not found (no errMsg)
```

代码中 `BattleLoadingSceneController` 配置分包名为 `"battle"`，但微信 `game.json` 中可能未匹配。检查 WX SDK 分包配置 → 导出后的 `Build/minigame/game.json` 中 `subpackages` 节点。

### 5.2 Windows 文件占用 IOException

`WeChatBuild.CleanBuildOutput()` 已加固：删不掉时自动重命名为 `.old`，不阻塞构建。常见锁文件元凶：微信开发者工具打开了 minigame 项目。建议把 `Build/` 目录加入 Windows Defender 排除列表。
