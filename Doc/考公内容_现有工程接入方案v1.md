# 考公内容接入现有工程 v1

日期：2026-10-11。本文是基于当前 C#、表结构和编辑器工具核对的实施方案，尚未修改正式源表、Prefab 或运行时代码。尚未读取全部 XLS 行来确定新 ID 空位；下文新 ID 只是示例。

## 1. 现有篇章的安排

保留美食篇与成语篇的内容、关卡 ID、通关记录和奖励关系。新增“考公闯关”主入口，第一批为数量关系；原有美食篇放在“休闲挑战”入口。成语篇保留，可逐步补充释义、易混词和语境题，成为后续语言模块的内容基础；仅改标题不等于完成考公内容适配。

产品入口与底层篇章编号分开。新玩家可直接进入数量关系第一关，不需要先打通美食和成语。旧玩家从休闲入口可继续原进度。第一批先接一关，再接五关，不同时改造全部内容。

## 2. 已确认的工程事实

| 已有实现 | 接入影响 |
|---|---|
| `LexiconCategoryTags` 中美食 ThemePackId=1，成语=2 | 为数量关系分配新的主题 ID；先核对源表避免重复 |
| `MonsterWordSpawnBinding` 根据怪物的 ThemePackId 与 CategoryTag 选词 | 主题来自怪物配置，不是自动由当前关卡篇章决定 |
| 主题没有候选词时，会回退到只按 CategoryTag 筛选的词池 | 新主题缺词时可能刷出其他篇章的词；需要隔离新主题的回退策略 |
| `ChapterLevel` 配置地图路径、前置关卡和奖励池 | 新关卡可以直接引用已有地图，不需要复制地图 Prefab |
| `unlockChapterId` 的实际语义是前置 levelId；0 表示默认开放 | 新训练第一关应独立开放，后续只依赖同主题前一关 |
| `ChapterLevelNavigation` 按 chapterId / levelId 排序找下一关 | 多入口后需要限定当前玩法的导航范围 |
| 首页默认开始逐个扫描已解锁关，遇到未解锁即停止 | 独立开放的新训练篇不能依赖这个全局扫描作为入口 |
| `HomeRoadmapView` 围绕当前篇章展示路线；篇章标题使用 chapterId 查主题标签 | 不能只在表末尾追加一章；路线展示与名称映射要配合新入口 |
| `BattleOutcomeCoordinator` 在打开结果面板前记录通关并发奖励 | 回忆题放在结果面板后；不用改奖励结算时机 |
| 当前胜利通过最终 Boss 或波次完成事件触发 | 45 秒是设计目标；硬计时结束是额外功能，不能仅改一个时长字段就宣称完成 |

## 3. 配表接入

修改 `Share/table/xls` 中的源表，再使用现有导表工具生成；不直接手改 `Assets/Script/Table/ProtoTable` 的生成类。

1. `c词汇表c.xls`：追加数量关系的短词；设置新主题 ID、分类、显示文字和权重。沿用现有 `MakeLexiconId` 规则，同时检查行主键与词条 ID 不重复。
2. `g怪物表c.xls`：复制少量现有文字怪配置，分配新怪物 ID，指定新 ThemePackId 和正确的 CategoryTag；复用现有文字怪预制体/底层行为。
3. `g关卡表c.xls`：追加新训练关卡，地图路径引用现有地图。第一关前置值 0；第二关前置值为新第一关 levelId；奖励先使用经核对可复用的奖励池。
4. `g关卡波次表c.xls`：新关卡引用新怪物 ID，配置短波次、稀疏开场、两次强化目标和终点。首关先做到约 45 秒战斗；严格到时结束需增加该训练关专用结束规则，确保与 Boss/波次事件互斥、仅结算一次。

候选示例：若 theme=3、chapter=3、level=301—305 经查均未占用，可使用它们；这只是编号选择，不要求玩家通关前两章。界面展示“行程训练·第1关”，不让内部编号决定产品文案。

即使 chapterId 与 ThemePackId 暂取同值，也通过显式主题元数据维护名称和玩法归属，避免后续一个主题拆多章时再次依赖两者相等。

## 4. 首页与导航

首版无需新增战斗场景或第二套选关系统。

- `HomeHubController.OnStartGameClicked`：主按钮先确定考公训练路线，再查该路线内的进度；通过已有 `SelectedLevelContext.Set(chapterId, levelId)` 和 `BattleFlowLauncher` 进入战斗。
- `HomeRoadmapView`：按当前选中的路线构建关卡列表。保留现有节点、星级和地图展示，增加入口/列表过滤。
- `ChapterLevelNavigation`：查询下一关及当前进度时增加路线限定。考公最后一关返回考公选关；休闲路线是否跨美食/成语章延续现有设计，不能自动串进数量关系。
- `CharacterSelectionPanel` 的开始入口也调用当前路线的统一解析，避免从角色页开始时又回到全局默认关。
- `LoginSceneController` 的快速开始路径检查同一入口规则；不通过把默认关 101 全局替换为新关来粗暴切换。
- `LexiconPreviewCatalog.GetThemeTabLabel` 增加新主题文案；章节标题采用对应主题元数据，不再隐式拿章号当词库主题号。

保存或传递“当前路线”，以支持结果页下一关、重新开始、返回首页后的连续体验。正式训练进度仍使用唯一 levelId 保存，不复制另一份战斗星级存档。

## 5. 题目、弹窗与知识进度

新增一份小型训练内容配置，建立 `levelId → conceptId → questionIds` 的关联。原型题目 JSON 需要转换为适合工程加载的固定字段与选项数组，不是拖入项目后就能直接生效的正式表。

建议数据项：知识 ID、标题、公式、条件；题目 ID、题干、选项数组、正确选项、解析；关卡 ID 与题目候选列表。首版内容本地加载，不需要 CDN 或新服务器接口。

建议新增运行时模块（以下名称是提案，不是已有文件）：

- `ExamContentCatalog`：加载并按关卡查训练内容。
- `KnowledgeProgressService`：记录接触、是否查看解析、独立回忆结果。
- `KnowledgeRecallPanel`：题目选择、提交、解析、跳过；共用已选定的卡通面板与按钮资源。

在 `GameResultPanel` 及其 Prefab 增加“回忆一道题”入口，仅当前关卡存在训练内容时显示。沿用现有再次挑战、下一关和返首页逻辑。答题不调用发奖/通关接口；避免多次打开结果页、重答或跳过导致重复奖励。

`PlayerSaveData` 当前版本为 5。接入知识字段时增加独立的数据项并更新版本迁移，旧档中的新数组默认空；沿用现有存档服务保存。保持旧关卡 ID、角色解锁条件、金币、背包和星级的含义。不要删除旧存档或重新解释 101/201 已有通关记录。

## 6. 两个容易遗漏的细节

**词库隔离**：新训练主题有显式主题 ID 时，应只取它的主题候选词。没有候选时给出可定位的配置错误，并使用明确的同主题保底词/保底配置；不随机回退到其他主题。原休闲篇章的回退是否更改，作为独立兼容性决策。

**字体覆盖**：`ExtractLexiconCharset` 当前提取表字段以及 C# / Prefab 中文；新增题目若放独立 JSON，需要将题干、选项、解析、公式、条件一并加入提取来源。复用现有字体，检查 ×、÷、单位与新汉字缺字，构建后再比较包体增量。

## 7. 最小实施顺序与验收

第一步：新增一个训练关与独立入口，确认刷的都是行程词；测试再次挑战、下一关、返首页及角色页开始不会串到旧篇章。

第二步：接一个结算后回忆题，跑通答对、答错、查看解析和跳过；基础战斗奖励各路径只发一次。

第三步：迁移知识存档并扩展剩余四关；用旧档确认旧章节进度、星级、角色与货币正常，用新档确认不用打休闲篇章也能进入训练。

第四步：换共用卡通 UI，检查新文字和公式显示；重新构建微信小游戏，对比实际资源增量和加载时间。不能凭题目文本大小估计整个改版包体。

通过第一步与第二步后才扩展成语的语境题与其他数学主题。已有美食/成语仅需逐步调整入口与内容定位，不需要先清空。
