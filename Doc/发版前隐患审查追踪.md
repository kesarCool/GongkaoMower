## P0 · 发包必修（6 条，全部经二次人工复核坐实）

### [ ] P0-1 ✎ 存档｜明文迁移通道使加密+校验和整体失效，改档即得任意货币/碎片

- **位置**：`Assets/Script/Game/PlayerData/Storage/EncryptedPlayerPrefsStorage.cs:41-47`
- **场景**：微信 wx storage 用户可写：把 `player_save_v1` 改成以 `{` 开头的明文 JSON（如 `{"gold":99999999}`），重启即生效，并被该通道"洗白"重加密为合法档。编辑器"模拟篡改"菜单写的是乱串、不以 `{` 开头，走密文分支被拦——**此洞自测永远测不出**。
- **证据**：`if (raw[0] == '{' || raw[0] == '[' || raw.StartsWith("guest_")) { json = raw; Save(key, json); return true; }`
- **建议**：砍掉或收紧明文迁移分支（仅首版升级窗口放行，并校验 version/playerId 一致性）。

### [ ] P0-2 ✎ 技能｜Legend 突破对共享 Prefab 资产读-改-写：scatterCount 每局 ×2 指数膨胀，AddComponent 效果跨局泄漏

- **位置**：`Combat/Skills/Implementations/SkillAutoProjectilePistol.cs:26-27`、`SkillAutoProjectileSword.cs:43`、`SkillAutoProjectileTalisman.cs:59`
- **场景**：WebGL 长驻会话连续多局选 Legend 手枪：守护变量 `_baseScatterCount` 是每局新建技能实例的字段、每局归零，快照到的都是上一局污染后的资产值 → 散射数 = 原值×2^k，几十局后一枪成百上千发子弹。剑/符箓的 `AddComponent<CritSplitOnHit>()/AddComponent<HomingOverride>()` 直接焊进资产，同会话后续所有对局（**含未突破角色**）永久继承。Editor 下改动残留在 Inspector，可能被误保存入库。
- **证据**：`maxLevelPrefab` 来自 `SkillDefinitionBase.cs:26` 的 SO 资产引用；`if (_baseScatterCount == 0) _baseScatterCount = scatter.scatterCount; scatter.scatterCount = _baseScatterCount * 2;`
- **建议**：突破效果改为发射时实例级注入（Instantiate 后再改值/加组件），资产只读。

### [ ] P0-3 ✎ 选卡｜选卡确认动画期间 Boss 转盘压栈：协程被杀、_cardConfirmationPending 永久卡 true → 死面板 + 游戏永久暂停

- **位置**：`Roguelike/UI/CardView.cs:319-321`、`Spawning/SpawnerWaves.cs:700`、`Roguelike/UI/CardSelectionPanel.cs:344`
- **场景**：Boss 死后 `DelayedBossCardSelection` 用 `WaitForSecondsRealtime(1.5s)` 计时，**timeScale=0 暂停期间照样走完**。玩家拾能量开选卡（暂停），在 1.5s 窗口内点卡：0.38s 确认动画进行中转盘 `UIManager.Open<BossWheelPanel>` 把选卡面板 `SetActive(false)` → `CardView.OnDisable` 杀协程 → `_onClick` 永不执行。该标志只在 `Show()`/`Hide()` 清（此场景两者都不发生）→ 转盘关闭后选卡面板复活但输入全禁，暂停锁无人释放。
- **建议**：选卡/转盘加会话互斥+队列管理；面板失活时回调兜底；realtime 衔接协程复查 `_isSelecting`。

### [ ] P0-4 ✎ 战斗｜复活流程窗口期击杀 Boss 被静默吞掉 → BossesAlive 卡死 → 复活后软锁，无补偿重放

- **位置**：`Battle/BattleOutcomeCoordinator.cs:124-128`
- **场景**：玩家与 Boss 同帧互杀（物理回调顺序不定，PlayerDiedEvent 先到、`_reviveFlowActive=true`），或死亡-复活面板间隙内遗留技能/子弹收掉 Boss：`OnEnemyDied` 直接 return，`RegisterBossKill` 永不执行。BossArenaLock 残留 → 复活后玩家被关在未解锁竞技场；中间波 Boss 则 `_waitingForBossKill` 死等。
- **证据**：`if (_battleEnded || _reviveFlowActive) { GameLog.Info("...SKIP..."); return; }`
- **建议**：胜负判定改状态轮询（见"建议修复顺序"第 2 条），事件只做加速器。

### [ ] P0-5 ✎ 战斗｜无终波 Boss 的关卡 100% 无法通关：一次性事件判定 + "轮询兜底"零消费者

- **位置**：`Battle/BattleOutcomeCoordinator.cs:171-178`、`Spawning/SpawnerWaves.cs:119/504`
- **场景**：关卡末波无 Boss 时（`UsesBossVictory=false`），`BattleWavesCompletedEvent` 在最后一批怪刷完瞬间发布——此刻怪必然 activeInHierarchy → `CountActive("monster") > 0` return，之后全工程无任何重查。`HasReleasedWaveCompletionSignal` 注释声称"供 BattleOutcomeCoordinator 轮询兜底"，**grep 全工程零消费者**。当前关卡若末波全配 Boss 则为潜伏雷，策划少配一行即炸。
- **建议**：同 P0-4，改状态轮询；无 Boss 路径每帧重入判定"波次完成 + CountActive==0"。

### [ ] P0-6 ✎ 战斗｜SpawnLimiter 满员 recycleOldest 把 Boss 直接回池（绕过 Die）→ 无死亡事件 → 软锁链

- **位置**：`Common/Pooling/SpawnLimiter.cs:84-96`、`Spawning/SpawnerWaves.cs:916`
- **场景**：SpawnLimiter 按 `"Enemy"` 类别键维护全局 FIFO（**Boss 与小怪同队**，SpawnerWaves 所有怪走同一 CanSpawn/RegisterSpawned）。Boss 波开场清场后 Boss 最早入队；场上活怪达上限（实测配置 maxAlive=100、recycleOldest=1）时下一次刷怪触发回收，Dequeue 出的正是 Boss → `GameObjectPool.Release` 不走 EnemyBase.Die、无 EnemyDiedEvent → BossesAlive 不减、竞技场不拆、死等。玩家视角："Boss 凭空消失，战斗再也无法推进"。
- **建议**：recycle 排除带 LastWaveBossMarker/Boss 组件的对象；或回收走 `Die()` 正常结算。
