# 被动技能（补给技能）设计方案

日期: 2026-05-30

---

## 一、概述

被动技能是肉鸽卡池中的**纯增益类技能**，装备后持续生效，不发射弹丸、不产生视觉特效（初期）。与主动技能共用 `ISkill` 生命周期，**但拥有独立的 5 个被动槽位**，不占用主动技能槽。

**双槽位设计**：
- 主动技能槽：5 个（现有 `MAX_SKILL_SLOTS`）
- 被动技能槽：5 个（新增 `MAX_PASSIVE_SLOTS`）
- 两套槽各自独立——抽卡时分别判断自己是否满槽
- 已装备技能不可替换（与主动一致），满槽后只出已有技能的升级卡
- 主动技能抽中概率减半是**预期行为**——增加决策难度，迫使玩家取舍

后续扩展：被动技能与角色主技能配置**羁绊关系**——装备了羁绊被动后，主动技能才能突破满级上限。

## 二、架构设计

### 2.1 核心原则

```
被动技能 = 一个轻量 SkillBase 子类
  OnEquip   → 写入属性加成到 PlayerHealth / PlayerSkills / PlayerController
  OnUnequip → 回退加成（恢复原值）
  Tick()    → NOOP（纯数值被动）或 regen/heal（有持续逻辑的被动）
```

**与主动技能的区别**：

| 维度 | 主动技能 | 被动技能 |
|------|---------|---------|
| Tick() | 生成弹丸/光束/刀片 | 空或低频（如每秒回血） |
| OnEquip | 初始化 SkillContext | 修改玩家属性 |
| OnUnequip | 清理 | 回退玩家属性 |
| SkillDefinition | 弹丸 Prefab、伤害表、CD | 属性加成值 per-level |
| 卡池模板 | newSkillTemplate（绿） | 可复用或独立模板 |

### 2.2 数据模型

#### SkillId 新增

#### PassiveSkillDefinition（新建 SO）

```csharp
[CreateAssetMenu(menuName = "Game/Skills/Passive Definition")]
public class PassiveSkillDefinition : SkillDefinitionBase
{
    [Header("被动类型")]
    public SkillId passiveId;              // 自己的 SkillId
    // 全家不覆盖；被动技能无变体，SkillFamily = id（默认）

    [Header("加成类型")]
    public PassiveModType modType;         // 枚举：加算/乘算/绝对值

    [Header("Per-level（size >= maxLevel）")]
    public float[] bonusByLevel;           // 每级加成值

    public float BonusAt(int level) => bonusByLevel[Mathf.Clamp(level, 1, bonusByLevel.Length) - 1];

    protected override string GenerateLevelDescription(int level)
        => $"+{BonusAt(level) * 100f:F0}%"; // 描述由子类定制

    protected override ISkill CreateRuntimeSkillInternal(SkillRuntimeBindings bindings)
        => new SkillPassive(passiveId, modType, BonusAt(1));

    public override void ApplyStatsToSkill(ISkill skill, int level)
    {
        if (skill is SkillPassive p)
            p.bonusValue = BonusAt(level);
    }
}
```

#### PassiveModType 枚举

```csharp
public enum PassiveModType
{
    Additive,       // 加算：新值 = 原值 + bonus
    Multiplicative, // 乘算：新值 = 原值 * (1 + bonus)
    Absolute,       // 绝对值覆盖：新值 = bonus
}
```

#### SkillPassive（运行时）

```csharp
public class SkillPassive : SkillBase
{
    public PassiveModType modType;
    public float bonusValue;
    public SkillId passiveId;

    private float _originalValue;

    public SkillPassive(SkillId id, PassiveModType type, float bonus)
    {
        Id = id;
        modType = type;
        bonusValue = bonus;
        passiveId = id;
    }

    public override void OnEquip(SkillContext ctx)
    {
        base.OnEquip(ctx);
        ApplyBonus(bonusValue);
    }

    public override void OnUnequip()
    {
        RemoveBonus();
        base.OnUnequip();
    }

    public override void Tick(float deltaTime) { /* NOOP */ }

    // 子类重写 ApplyBonus / RemoveBonus
    protected virtual void ApplyBonus(float value) { }
    protected virtual void RemoveBonus() { }
}
```

### 2.4 CardDeck 双槽适配

```csharp
// Draw() 新增参数
public List<DrawResult> Draw(int currentLevel, PlayerSkills playerSkills, ...)
{
    // 判断技能类型
    bool isPassive = IsPassiveSkillId(def.id);
    bool hasSkill = isPassive ? playerSkills.HasPassiveSkill(id)
                              : playerSkills.HasSkill(id);
    bool hasEmptySlot = isPassive ? playerSkills.HasPassiveEmptySlot
                                  : playerSkills.HasEmptySlot;
    bool isFull = isPassive ? playerSkills.IsPassiveFull
                             : playerSkills.IsFull;

    // 满槽且未拥有 → 排除
    if (!hasSkill && isFull) continue;
    // 满槽且未拥有且不允许新技能 → 排除
    if (!hasSkill && !hasEmptySlot && !allowNewSkillWhenFull) continue;
}
```

### 2.5 加成应用模式

每种被动写一个轻量子类，重写 `ApplyBonus` / `RemoveBonus`：

```csharp
// 示例：血量上限 +20%
public class SkillPassiveMaxHp : SkillPassive
{
    protected override void ApplyBonus(float value)
    {
        var health = _ctx.player.GetComponent<PlayerHealth>();
        _originalValue = health.MaxHp;
        health.SetMaxHp(_originalValue * (1f + value));
        health.ResetToFull();
    }

    protected override void RemoveBonus()
    {
        _ctx.player.GetComponent<PlayerHealth>()?.SetMaxHp(_originalValue);
    }
}
```

--- 所有 PassiveSkill 子类都遵循这个模板：OnEquip 保存原值 + 写入新值，OnUnequip 恢复原值，Tick 空。

### 2.4 Definition 到 Runtime 的工厂

与主动技能完全一致：

```
PassiveSkillDefinition (SO)
  → CreateRuntimeSkillInternal()
    → new SkillPassiveXxx(...)
  → ApplyStatsToSkill()
    → p.bonusValue = BonusAt(level)
```

`SkillCatalog` 和 `CardDeck` 无感知差异——所有 `ISkill` 统一对待。

## 三、被动技能列表（按实现难易分级）

### L1 — 纯数值乘算（1 个子类，5 种被动）

**实现方式**：一个泛型子类 `SkillPassiveStatMul`，在 OnEquip 中读取目标字段原值、乘以 `(1 + bonus)`、写入新值。每种被动只需配置不同的目标字段。

| SkillId | 名称 | 效果 | 字段 | modType |
|---------|------|------|------|---------|
| 101 | 钢筋铁骨 | 血量上限 +X% | PlayerHealth.maxHp | Multiply |
| 102 | 锋芒毕露 | 攻击 +X% | PlayerSkills.attackMultiplier | Multiply |
| 103 | 健步如飞 | 移速 +X% | PlayerController.moveSpeed | Multiply |
| 104 | 铁壁铜墙 | 防御 +X% | PlayerHealth.defense | Multiply |
| 105 | 致命一击 | 暴击率 +X% | PlayerSkills.critRate | Add |

**工作量**：~30 行泛型类 + 5 个 SkillDef SO + 5 个 SkillId

### L2 — 需要 Tick 逻辑（独立子类）

| SkillId | 名称 | 效果 | 实现要点 |
|---------|------|------|---------|
| 106 | 生生不息 | 每秒恢复 X% 最大血量 | Tick 中累加 deltaTime，>=1s 时 `Heal(maxHp * value)` |
| 107 | 疾风迅雷 | 所有攻击间隔 -X% | OnEquip 遍历所有已装备 ISkill，修改 interval/cooldown 属性；OnUnequip 恢复 |

**L2 特有坑点**：
- #106 需要 `PlayerHealth.Heal(float)` 新增方法
- #107 需要遍历 `PlayerSkills` 中所有技能实例，直接修改字段（`interval`/`cooldown`），并且**后续新装备的技能也要减**——需要挂钩子

### L3 — 需要修改非玩家组件（独立子类）

| SkillId | 名称 | 效果 | 实现要点 |
|---------|------|------|---------|
| 108 | 磁力吸附 | 拾取范围 +X% | 修改 `Magnet` 或 `Pickup` 组件的 range 字段 |
| 109 | 金刚不坏 | 受到伤害 -X% | OnEquip 修改 `PlayerHealth.defense` 的等效计算，或在 `TakeDamage` 前加钩子 |

**L3 特有坑点**：
- #108 需要确认掉落物吸附组件是否存在、range 字段是否 public
- #109 简单方案是直接叠加 `defense`（乘算），效果近似

### L4 — 需要新 Event 或复杂交互

| SkillId | 名称 | 效果 | 实现要点 |
|---------|------|------|---------|
| 110 | 横扫千军 | 弹药范围 +X% | 修改 `PlayerBullet` 子类的 collider 大小 / AO E半径 |
| - | 浴血奋战 | 击杀回血 | 订阅 `EnemyDiedEvent` |

**L4 暂不做**——等羁绊系统确定后再排期。

## 五、潜在坑点

### 5.1 设计层

| # | 坑点 | 严重度 | 说明 |
|---|------|--------|------|
| P1 | OnUnequip 回退顺序 | 高 | 多个被动叠加同一个字段时，回退顺序必须与装备顺序相反（栈式），否则中间被动的原值被污染。解决方案：每个被动独立存 `_originalValue`，在 Apply 时读取当前值作为自己的原值 |
| P2 | ~~槽位挤占~~ | 已解决 | 双槽设计：被动独立 5 槽，不占主动槽 |
| P3 | 暴击率加算 vs 乘算 | 中 | `critRate += 0.15`（加算）可能溢出 1.0。需 `Mathf.Clamp01`。且多个被动叠加可能直接满暴击 |
| P4 | 家族冲突 | 低 | 被动技能 SkillFamily = 自己的 ID（无家族），不会与主动技能互斥。但如果后续想让同类被动互斥（如不能同时带"攻击+15%"和"攻击+30%"），需要新增家族 |

### 5.2 实现层

| # | 坑点 | 说明 |
|---|------|------|
| P5 | ApplyBurstStats 只认 AutoProjectile | 如果被动是 AutoProjectile 系的羁绊被动，SkillFamily 需要特殊处理 |
| P6 | GetFinalDamage 已应用 attackMultiplier | 被动修改 `attackMultiplier` 后，所有主动技能的 `GetFinalDamage()` 自动生效——**这是预期行为，不用改任何主动技能代码** |
| P7 | Tick 性能 | 每个被动 `Tick(float dt)` 每帧调一次。L1 被动 Tick 为 NOOP，开销为一次虚函数调用 + 一个 if(_equipped) 检查，5 个被动约 0.01ms |
| P8 | 对象池残留 | `SkillPassive` 不涉及 GameObject 或 Pool，无此坑 |
| P9 | CardDeck 模板 | 当前只有 newSkillTemplate/upgradeTemplate/breakthroughTemplate 三个模板。被动技能可能需要独立视觉模板（如蓝色），否则玩家分不清主动/被动卡 |

### 5.3 卡池层

| # | 坑点 | 说明 |
|---|------|------|
| P10 | 权重膨胀 | 预期行为：卡池候选翻倍，主动技能抽中概率减半，增加决策取舍。若后续觉得过于稀释，可通过 CardPoolProgression 调权重 |
| P11 | 双槽满槽判断 | 主动槽和被动槽各自独立判断满槽。`allowNewSkillWhenFull` 分别作用于两套槽位。被动满槽时不出新被动，只出已有被动升级卡 |

### 5.4 羁绊层

| # | 坑点 | 说明 |
|---|------|------|
| P12 | 羁绊降级 | 如果满级后失去羁绊被动（卖了、被替换），主动技能等级应该退回 maxLevel 而非 BondedMaxLevel。需要监听 OnUnequip 事件降级 |
| P13 | 羁绊循环 | 多个主动技能共用同一被动做羁绊时，被动被替换 → 所有依赖它的主动技能都要降级 |
