# 微信小游戏上线整改方案

## 当前状态

| 包 | 大小 | 限制 | 状态 |
|----|------|------|------|
| 主包 | ~1.1M | 4M | ✅ 通过 |
| wasmcode 分包 | 5.4M | 20M | ✅ 通过 |
| data 分包 | 18M | 20M | ✅ 通过 |
| **总计** | **~25M** | 200M | ⚠️ 合法但臃肿 |

> 主包不超限，审核不会卡。下面解决**质量和浪费**问题。

---

## 一、字体裁剪：13MB → 500KB 以内

### 现状
`msyh SDF.asset` 含 20000+ 汉字，13MB。文字割草每个敌人 7 个字，实际最多用到词典中几百个不同汉字。

### 方案

**Step 1**: 从配表提取所有用到的汉字

LexiconTable.bytes 中的 `DisplayText` 字段包含了所有词条。写一个 Editor 工具：

```
菜单: Tools/提取词库字符集
1. 读取 LexiconTable.bytes (FlatBuffer)
2. 遍历所有行的 DisplayText
3. 收集所有不重复汉字 → 输出 charset.txt
```

**Step 2**: 用 TMP Font Asset Creator 重新生成字体

```
Window → TextMeshPro → Font Asset Creator
- Source Font File: msyh.ttf (微软雅黑原版) 或选 Anyuan.ttf / PingFang 等免费字体
- Character Set: Custom Characters
- 把 charset.txt 中所有字粘贴进去
- Atlas Resolution: 2048x2048（几百字够用）
- 生成后替换 Assets/Resources/Fonts/msyh SDF.asset
```

预估结果：500 个汉字 → atlas 2048 → ~300KB（SDF 小字版）。

**Step 3**: 兜底——词典新增字时自动补

`EnemyWordLabel.SetWord` 里 `AgentDbgTmpFontCoverage` 已经在记录缺失字符。
加一行：如果 `missingCount > 0`，输出警告日志提醒策划补字。

### 风险评估
- 如果配表新增词条含新字且未重新生成字体 → TMP 显示为方块
- 解决：每次更新配表后重新提取字符集 + 重生成字体，脚本化一条命令即可

## 二、地图方案：放弃 Tilemap，极简三色瓦片

### 现状
- Game.unity 3.3MB，地图纹理 4.3MB，222 种 tile PNG
- 13 个小关卡，只用了其中一小部分瓦片

### 方案：只保留 8 个纯色/简单 tile

**地图设计**：三章 × 不同色调

| 第一章（新手村） | 第二章（暗色） | 第三章（熔岩） |
|------------------|----------------|----------------|
| 草地 #4CAF50 | 暗灰地面 #37474F | 暗红地面 #5D4037 |
| 土路 #A1887F | 石板路 #546E7A | 焦土 #3E2723 |
| 水域 #64B5F6 | 深渊 #263238 | 岩浆 #FF5722 |
| 围墙（纯色边界） | 围墙 | 围墙 |

**实现**：
- 8 个 32x32 纯色/简单纹理 PNG，总共不超过 10KB
- 删除 `Assets/Res/Map/Textures/Style01/` 下全部 222 张旧 tile
- 保留 1 个 Tile Pallete 文件
- 重新拼 3 张地图 × 不同色调调色板
- 预期：地图资源从 4.3M → <50KB

**Game.unity 瘦身**：
- 删除旧 Tilemap Grid 数据
- 只保留 3 个 Tilemap（Ground, Wall, Water）
- 场景文件预计从 3.3M → <300KB

## 三、技能架构：改数据驱动，不改设计

### 你现在的问题不是"五个技能太少"

是每个技能 = 两个文件 × 五层继承 × 手写逻辑。加一个技能要写 Definition + Implementation + Editor Setup，维护成本 O(n)。目标 10 个技能的话按现在架构会炸。

### 改造方案：保留核心逻辑，抽成数据驱动

```
旧架构：
  AutoProjectileSkillDefinition.cs + SkillAutoProjectile.cs
  GrenadeSkillDefinition.cs + SkillThrowGrenade.cs
  LineBeamSkillDefinition.cs + SkillLineBeam2D.cs
  OrbitingBladesSkillDefinition.cs + SkillOrbitingBlades.cs
  FieldGeneratorSkillDefinition.cs + SkillFieldGenerator.cs

新架构：
  SkillConfig (ScriptableObject)  ← 一张表定义所有技能参数
    ├─ skillType: enum { Projectile, Grenade, LineBeam, Orbit, Field, ... }
    ├─ damage: float
    ├─ cooldown: float
    ├─ projectilePrefab: GameObject
    ├─ count: int
    ├─ speed: float
    ├─ radius/range: float
    └─ upgradeTable: UpgradeConfig[]

  SkillRunner.cs  ← 一个通用执行器
    └─ 根据 SkillConfig.skillType 走不同分支
```

```
// SkillRunner 核心（伪代码）
public void Execute(SkillConfig cfg, int level) {
    var data = cfg.GetUpgradedData(level);
    switch (cfg.skillType) {
        case SkillType.Projectile:  SpawnProjectiles(data); break;
        case SkillType.Grenade:     ThrowGrenade(data); break;
        case SkillType.LineBeam:    CastBeam(data); break;
        case SkillType.Orbit:       SpawnOrbits(data); break;
        case SkillType.Field:       CreateField(data); break;
    }
}
```

**收益**：
- 新增一个技能 → 只新增一个 SkillConfig.asset，填参数
- 10 个技能 = 1 个 SkillRunner.cs + 10 个 ScriptableObject，不是 20 个 C# 文件
- 数值策划可以在 Inspector 调参数，不用改代码
- Editor 自动化：选 skillType 后自动展开对应参数面板

### 五个技能够不够？

文字割草核心乐趣是"打字 → 消怪 → 走位"。技能是辅助。**5 个类型够了，10 个也可以**，关键不是数量是差异化：

| 建议保留 | 定位 |
|----------|------|
| 自动弹射 | 清群怪 |
| 手榴弹 | AOE 爆发 |
| 环绕刀 | 近身防御 |
| 光束 | 方向性高伤 |
| 力场 | 区域控制 |

如果要加到 10 个，在此基础上加：
- 冰霜新星（减速）
- 闪电链（弹跳）
- 毒雾（持续伤害）
- 闪现/冲刺（位移）
- 召唤物（炮塔）

核心原则：**每个技能的功能差异要对战斗决策有意义**，不是换皮。

## 四、音效方案：最小可用方案

### 当前：0 个音频文件

文字割草的音效优先级：

| 优先级 | 音效 | 来源 |
|--------|------|------|
| P0 | 键盘打字音（核心） | 免费音效库 / 自己录 |
| P0 | 怪物死亡音 | 同上 |
| P1 | 技能施放音 × 5 | 每个技能 1 个 |
| P1 | UI 点击音 | 通用 |
| P2 | 受击音 | 通用 |
| P2 | BGM（可选，微信小游戏常静音） | 8-bit loop |

### 实施方案

1. 去 [freesound.org](https://freesound.org) 或 [mixkit.co](https://mixkit.co/free-sound-effects/) 下载免费音效
2. 全部转为 mono 22050Hz OGG，每个 <50KB
3. 12 个音效 × 50KB = 600KB 总量
4. Unity Audio Source 池化管理，WebGL 下使用 `UnityWebRequest` 异步加载
5. 微信小游戏环境下 `wx.createInnerAudioContext` 代替 Unity Audio（WX SDK 已封装，参考 `Assets/WX-WASM-SDK-V2/Runtime/wechat-default/unity-sdk/audio/`）

## 五、纹理压缩

### 现状问题

| 文件 | 大小 | 问题 |
|------|------|------|
| GRENADE EXPLOSION.png | 3.2M | 4096x4096 RGBA 无压缩 |
| sheet_impact_fire.png | 583K | 未压缩 |
| 40 张 UI 纹理 | 938K | 可能未开压缩 |

### 方案

**Unity Texture Importer 设置**（全选 Texture → 批量修改）：

| 参数 | 值 |
|------|-----|
| Max Size | 2048（特效）/ 1024（UI） |
| Compression | RGBA Crunched ETC2（Android）/ ASTC（iOS/鸿蒙） |
| Crunch Quality | 50 |
| Filter Mode | Bilinear |
| Generate Mip Maps | 关闭（2D 游戏不需要） |

预估效果：
- GRENADE EXPLOSION.png: 3.2M → ~200K
- sheet_impact_fire.png: 583K → ~80K
- UI 纹理合集: 938K → ~200K

**WX SDK 纹理压缩**：
微信小游戏 SDK 支持自动纹理压缩（`unity-namespace.js` 中 `usedTextureCompression` 已开启），构建时会自动处理。确认 PlayerSettings 中 Texture Compression 已开启。
