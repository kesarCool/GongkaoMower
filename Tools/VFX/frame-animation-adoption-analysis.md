# AI 序列帧流程在《文字割草机》中的接入分析

2026-10-26 更新：三个样本及 1.5 倍时长已完成 Editor 验证，通用导入 / 预览工具与配置库已落地。后续制作统一使用 [技能视觉制作手册](README.md)。本文保留最初分析与实施提案。

日期：2026-10-25。依据用户提供的《帧动画生成完整流程.md》、山海特效图鉴 Demo、本工程当前代码、Prefab 和已有战斗截图。

本文为静态分析与实施提案。完成了素材文件校验和部分图集目视检查；没有启动 Demo 或 Unity 战斗验收，没有生成新美术或修改战斗代码。

## 1. 结论

**可以采用，并且现有工程已经具备其中一部分能力。最有价值的方向是建立我们自己的轻量特效资产流程。**

优先用于手雷爆炸、落雷、符咒命中、刀光、突破瞬间与局外升级反馈。保留程序控制的弹道、范围、碰撞和伤害，序列帧负责局部视觉变化。高频子弹、长光束、常驻光环以及角色多方向动作，应分别选择更合适的表现方式。

这套流程实质是：技能视觉设计 → AI 生成多格图集 → 检查和修正 → 引擎按帧采样 → 与轨迹、粒子和游戏事件组合 → 预览与验收。它不能自动保证连续动作、正确透明度或游戏中的最终效果。

我们应建立自己的风格、时序、规格、接入工具和验收标准；“换成我们的东西”需要重新设计视觉主体，单纯改名、换色无法完成风格适配。

## 4. 哪些适合做，哪些应保留现有方式

| 表现类型 | 适合程度 | 我们的用法 |
| --- | --- | --- |

| 雷霆万钧 | 高 | 瞬时落雷 + 短余电；评估替换现有层数，避免继续叠加复杂粒子 |
| 天师符令命中、刀光剑影斩痕 | 高 | 小图集、短播放、限制同屏数量；弹体与轨迹仍按程序运动 |
| 导弹命中 | 高 | 与手雷共享基础库，必要时使用不同冲击轮廓 |
| 技能突破、角色升阶反馈 | 高 | 低频短表现，结合既有 UI/角色位置播放 |
| 高频普通子弹 | 局部适合 | 只增强枪口和少量命中火星；不为每发弹制作大型 16 帧动画 |
| 气贯长虹 | 局部适合 | 继续用 Mesh 表现任意长度、分色和贯穿；图集仅用于束头或命中 |

| 角色多方向移动、复杂攻击 | 不作为本流程首批 | 需解决轮廓、服装、武器、脚底定位和方向一致性；优先评估现有分件/骨骼方式 |

## 5. 必须改造的四件事

### 风格和镜头

统一为当前项目的明快卡通和实际战斗镜头。用清楚的外轮廓、有限主色、少量碎屑表达力量，避免满屏白光和复杂神兽实体。脚底效果使用统一落点；定向攻击统一朝右基准，程序按攻击方向旋转。带地面透视的图不能随意旋转后仍假设透视正确。

文字怪是主要阅读对象。特效的核心、外缘、地面层需分别控制大小、透明度和排序；必要时把大效果拆为后景地面环与前景冲击，不能用一个巨大不透明面片盖住文字。

### 透明度与混合

对方运行包确实包含按 RGB 最大分量计算能量、剔除近黑像素的 shader；对 authored 分支还会计算透明度和边缘淡化。代码对不同效果选择不同混合，不能认定 Demo 全部采用同一种模式。

我们应区分两类交付：

- 火花、雷光、亮芯等纯能量层：可测试黑底加法混合，在本工程浅色地图上检查是否泛白。
- 烟、纸片、墨迹、实体符片等需要保留遮挡或暗色细节的层：优先交付经过检查的 RGBA，采用匹配的透明材质。

将黑底简单阈值删除，容易损坏暗色主体；按亮度做 alpha 也不能恢复已经丢失的真实透明信息。正式资产要检查黑边、边缘色、透明模式和淡出，不能只在黑色预览底上判断合格。纯能量与实体层必要时分别生成和组合。

### 帧布局和节奏

4×4 只是布局方案，16 帧不必成为所有效果的硬标准。小命中可先试 4–8 帧，爆炸可试 8–16 帧，再按实机尺寸判断收益。

建议正式运行图优先试 512×512 或 1024×1024，确保格尺寸明确。AI 输出尺寸未必遵守提示词，必须检查实际文件。对于 1254×1254 这样的已有源图，可以使用分数 UV；若采用 Sprite 切片，应定义正确的矩形边界或统一派生输出，避免直接整数等分造成累计偏移。转换后的画质要再验收，原文件保留。

滤波引起的邻格串色需要安全边距、格内 UV 内缩或合适的边缘处理；单纯把整张图设为 Clamp 不能解决内部格子串色。

手雷在落地时已结算伤害，爆炸动画应迅速进入冲击帧，不能把较长蓄力安排到命中以后。AI 提示词中的“凝聚→展开→爆发→消散”不是通用时序；需要蓄力时，应明确接到既有释放前阶段，不延后当前伤害。动画结束不承担伤害结算职责。

### 包体和渲染成本

序列帧是用纹理存储换取部分运行时表现工作，并不自动更省性能。对象池减少对象创建和销毁，不会消除透明过绘、纹理内存或材质切换。

以 RGBA32、无 mipmap 计算，单张 512 图约 1 MiB、1024 图约 4 MiB、2048 图约 16 MiB。16 张 1254 图若全部按 RGBA32 常驻，像素数据约 95.98 MiB；这只是说明成本的假设，不是本工程实际格式或实测显存。压缩、解码和加载策略会改变最终占用。

`ArtOutput/BuildAudit/20261024/report.md` 记录当次微信导出为 23.05 MiB、按该报告采用的口径余量为 6.95 MiB。这是历史构建记录；本轮没有重新审计当前构建，也不据此保证新增资源能够入包。每轮都应比较相同设置下的新旧构建实际增量。

## 6. 建议采用的工程路线

第一阶段沿用粒子图集：一个新特效 Prefab，主体为单次发射的序列帧粒子，按需附加轻量扩散环或碎屑，挂现有 PooledCombatVfx，由 CombatVfxSpawner 播放。配置确定性帧序、寿命和回收时间，复用材质；测试排序、首帧方向、暂停和重复借还。

Unity 2021.3 的 [Texture Sheet Animation 官方文档](https://docs.unity3d.com/2021.3/Documentation/Manual/PartSysTexSheetAnimModule.html) 支持 Grid、Whole Sheet、按生命期曲线或指定 FPS 取帧；这些能力足以完成首个短爆炸样本。实际视觉仍需在当前项目材质下验证。

只有当飞行/命中分段、指定循环段、复杂混合或精确逐帧控制确有需求时，再新增通用配置和播放器。若实现 Sprite 播放器，需要扩展生命周期适配，保证 Play、暂停、复用重置、寿命结束、提前回收和限流注销一致；不能只挂组件就假设 PooledCombatVfx 会驱动它。一个实例只保留一个回收责任方。

短期工具建议，均尚未实现：

1. 图集导入检查：尺寸、帧数、透明数据、边距、帧序和命名，自动应用选定导入预设。
2. Unity 特效预览：浅底、深底、实际地图，支持逐帧、变速、真实尺寸、多个实例叠加与文字怪对照。
3. 特效清单：记录 vfxId、用途、纹理、布局、帧段、时长、锚点、视觉尺寸、混合、层级和质量档；并保留提示词、参考图、原始输出、修正版本与最终选择。

源图和评审文件可放 `ArtOutput/VFX/`，精选运行资产放 `Assets/Res/Textures/VFX/`、`Assets/Res/Materials/VFX/`、`Assets/Res/Prefabs/Effects/`。这是建议目录，不代表已创建或接入。

## 7. 形成我们自己的制作规范

每个任务先写清：实际技能事件、命中位置、伤害发生时间、视觉半径、频率、最大并发、持续时间、镜头、图集布局、透明方案与可读性限制。再生成少量候选图，逐帧检查，淘汰变形、串格、中心漂移和裁切的版本。

以“石破天惊”作为首个原创效果，可将视觉定义为橙金卡通冲击、简洁烟团和少量碎屑，中心有力、外圈稀疏，避免复制对方火焰法阵。以下为后续试制的提示词草案，本轮没有执行生成：

> 为《文字割草机》制作一张短促手雷爆炸序列帧图集。采用提供的实际战斗截图作为风格与镜头参考，明快卡通、清晰轮廓、橙金主色、少量烟团与碎屑。4 列×4 行，按从左到右、从上到下排列，为同一次爆炸的连续动作。所有格子镜头、中心和尺度基准一致，每格四周留至少 12% 安全边距，不跨格、不裁切、无分隔线、无文字、无场景和角色。爆炸起始即出现冲击亮核，随后扩散和消散，末帧接近消失；不安排长蓄力。交付经过检查的透明 RGBA，不含棋盘格。主体面积适中，外围稀疏，适合浅色地图和文字怪同屏。

提示词不能保证输出尺寸、透明边缘和动作连续性。若最终选择黑底能量层，需单独约定加法材质，不能混用上述 RGBA 交付标准。前述参考截图也需在真正生成时作为参考输入提供。

分享包中未见明确授权说明；对方图集先作为技术和视觉参考，正式资产采用我们自己的设计、生成与修正记录。

## 8. 首批试制与验收

建议分三步推进，每一步通过后才扩展：

1. **石破天惊爆炸**：验证一次性 4×4 图集、透明度、现有池化回收与原伤害同步。只绑定一个技能先对比；现有爆炸资源被多个技能共享，避免直接替换公共文件产生连带变化。
2. **天师符令命中**：验证小尺寸、短播放与高频限流。普通 PlayerBullet 当前没有通用命中 VFX 钩子，应在真实命中路径补一个轻量入口，不能假设换 Prefab 已能触发。
3. **雷霆万钧**：比较现有多粒子层与新图集组合，在多技能叠加时检查可读性与性能。

首次调参可将爆炸主体试在约 0.3–0.5 秒、符咒短印记约 0.12–0.22 秒、落雷及余电约 0.25–0.45 秒。这些是试制起点，不是已验证参数，需按实际释放频率与画面调节。

每一步需检查：

- 图集：帧序、中心、边缘、透明度、结束帧，不能用静态美观替代播放验收。
- 战斗：在真实事件触发，位置和视觉范围对应实际技能，伤害/冷却/索敌/暴击/突破保持原规则。
- 生命周期：快速连续播放、暂停恢复、选卡、回池重用、技能卸下、重开与场景退出，无残留和重复回收。
- 可读性：浅深地图、普通/满级/突破、多技能叠加时，文字怪和危险提示仍可辨认。
- 性能与构建：同一机型与场景比较帧时、内存、批次/过绘和微信导出增量；记录并发、限流及降级表现。

这证明「原创生成原稿 → 选帧缩小并共用图集 → 在原技能事件接入 → 真实施放与生命周期验证」可以用于本工程。资源尺寸、层数和限流应按技能定义，不照搬分享包的特效层数与分辨率。微信真机性能及最终构建增量仍需后续专项验证。

“文件能播放”“Unity 预览正确”“真实技能能触发”“微信真机合格”分别验收。完成首个爆炸样本后，再决定通用播放器和批量制图的投入规模。
