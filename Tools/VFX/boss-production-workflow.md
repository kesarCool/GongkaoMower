# Boss 技能视觉生产工作流

版本 1.0，2026-10-29。适用于《文字割草机》当前 Unity Built-in 2D / 微信小游戏工程。以后制作或改版 Boss 技能，从本文开始；现有成品、代码、配置、构建菜单、实战报告和录像集中在[产出总目录](boss-deliverables.md)。

```mermaid
flowchart LR
    A[查机制与旧表现] --> B[填写任务单与预算]
    B --> C[复用资源 / 网格字形 / 新美术]
    C --> D[专用构建与配置检查]
    D --> E[真实技能与生命周期验收]
    E --> F[原速回放与观感反馈]
    F --> G[登记配置与交付目录]
    F -->|需调整| B
```

## 1. 查清机制，留下修改前基线

从真实 `Monster.element / elementNum`、`LevelWave`、EnemyCatalog 和 [BossBrain](../../Assets/Script/Game/Enemies/Boss/BossBrain.cs) 追到具体模块及实际资源注册。分清“模块名字”“真实运行行为”“配表有没有使用”，记录冷却、首次等待、锁向时刻、数量、速度、距离、半径、伤害、判定方式和触发事件。

在改代码 / Prefab 前保存相关原文件和原速回放；基线、机制观察与文件哈希放入 `ArtOutput/VFX/<任务>/Baseline/` 及该任务的证据目录。备份放在 Assets 外，避免旧脚本重复导入。已有历史报告只能证明当次观察，不能替代本次改动前后的实测。

**本阶段产出：**任务单中的机制基线表、目标 Boss / 关卡、真实触发入口、修改前截图 / 回放、原文件保护清单。

已知的三个例子必须保留：小刀虽然模块叫 `homingKnife`，实际仍直飞；冲刺旧伤害查询有命中自身的限制；地裂原预警只有约 0.14 秒，改为 0.7 秒是玩法调整。不能根据名称、发光或配置里的伤害数字判断机制已生效。

## 2. 写视觉分镜和资源预算

复制 [Boss 任务单](Templates/boss-skill-brief.md) 到 `ArtOutput/VFX/<任务>/brief.md`，按实际事件填写“预警 / 蓄力 → 释放 → 飞行或持续 → 命中 → 收招 / 消退”。被动复活写“致命伤 → 等待 → 恢复 → 保护结束”。每个阶段都写清最终秒数、开始 / 结束事件和取消行为。

敌方效果以朱红 / 橙金为主，深酒红边界、小面积暖白亮芯；在浅沙、草地和深底可读。优先通过轮廓、短暂展开、旋转方向和留白提升表现，不依赖大面积白闪或堆叠透明层。角色字形与攻击信息同时保持清晰。

| 表现用途 | 坐标来源 | 必须保持的关系 |
| --- | --- | --- |
| 地裂、冲刺危险范围 | 实际世界位置与碰撞范围 | 视觉边界、锁向与真实判定一致 |
| 刀气 / 小刀飞行图形 | 弹体方向及 Collider | 缩放视觉子级，保持物理根与真实数量 |
| 出手闪、身体重影、冠徽 | TMP 可见字形 / 显式身体节点 | 不把全部身体表现绑到 transform 原点 |
| 召唤门印 | Spawner 成功生成后的最终位置 | 地图 / 墙体约束完成后再显示 |
| 复活字形与护弧 | 实际字体四边形、恢复事件、真实盾状态 | 同一字形回聚，保护弧与真实免伤寿命一致 |

预警 / 锁向 / 判定 / 追踪 / 技能分配一旦改变，在任务单独立写“原值 → 新值、理由和验证”。观感时长、弹体寿命、池回收时间分别填写；最终秒数不再套用历史通用 1.5 倍系数。

**预算默认：**先争取 0 新 PNG / 材质；填写实际并发、渲染器 / 网格数量、图集与材质复用、源 PNG 预算。资源增长要能对应清晰的视觉收益。

## 3. 选择最省资源的实现

| 路线 | 适用内容 | 当前可复用产出 |
| --- | --- | --- |
| 现有图集＋小参数差异 | 敌方短刃、命中小消散 | [刀气](boss-blade-burst-v1.md)、[小刀](boss-dash-knife-v1.md)共用一张 512×256 图集 |
| 确定性网格 | 范围圈、方向带、符环、冠徽、裂纹、保护弧 | 冲刺、召唤、地裂、公共头标；复用实体材质 |
| 实际字形快照 | 分身蓄力重影、死亡散字与回聚 | 分身、复活；共享实际字体材质，按材质合批 |
| 新透明原稿 | 现有轮廓无法表达的新火团、刃形或帧动画 | 使用 [Boss 美术提示词](boss-production-prompts.md)与[通用图集模板](prompt-templates.md)，保留原稿和取舍记录 |

程序几何和字形不需要为了流程而生成图片。新原稿放 `ArtOutput/VFX/<任务>/Sources/`，提示词放同级 `prompts.md`；进入 Assets 的是筛选、裁切、缩放与打包后的正式资源。

当前新增 Boss 特效图集按路径去重为一张，源 PNG 28,653 字节；后续复用不再重复计算这笔纹理预算。源图字节、ETC2 块数据、运行内存和最终微信上传包分别记录，禁止互相代用。

## 4. 接入组件、配置与构建器

沿用 `技能模块 → 独立 Presentation → 共享资源` 的关系。模块负责真实时序、方向、生成和伤害；表现负责可视阶段、锚点和网格。表现不得额外抽取玩法随机数、提前显示失败生成或推迟真实敌人的可碰撞时间。

在 `Tools/VFX/Library/Boss/` 增加专用版本配置和 `Assets/Editor/Boss<名称>V<版本>Builder.cs`。明确哪些字段会写入序列化组件，哪些只是必须匹配代码的节奏契约 / 机制记录；改 JSON 后运行构建与配置检查，不把编辑 JSON 当作已经改好 Prefab。

按适用范围同步 `boss_common`、`boss_30001`、`boss_30002`、`boss_30003` 四份兼容 Prefab。保留原技能注册、物理字段、发射节点和其他已完成表现，给新弹体使用明确的独立注册 key。重复构建应复用组件与资源，核对文件 / GUID 一致性。

技能全流程配置不交给普通一次性粒子导入器；小消散等单次效果可单独登记普通配方。危险预警和真实弹体完整显示，装饰限流只应用在可以省略的小消散等反馈。

**阶段结束条件：**编译成功、专用配置检查通过、目标 Prefab 引用正确、资源预算更新；仅做到此处仍属待实战验证。

## 5. 用真实技能验收

先单技能，再针对本次改动做组合 / 回归。使用真实 Game、真实模块和实际碰撞 / 伤害探针；验收场景使用内存存档。未配表能力可以在隔离夹具临时注入，并在报告标明，不能冒充正式关卡已启用。

| 检查组 | 本项目要求 |
| --- | --- |
| 机制 | 真实数量 / 属性 / 伤害 / 半径 / 时序；有意修改项与原值对照 |
| 可读性 | 浅沙、草地、深底、实际战斗尺寸、贴字 / 世界锚点与多个技能叠加 |
| 生命周期 | 暂停恢复、连续施放、不同阶段禁用 / 死亡 / 假死 / 回池 / 重建 / 退场 |
| 复用 | 旧预警、尾迹、残痕与回调不污染新租约；没有逐轮增长的纹理 / 材质 / 临时对象 |
| 分身 / 召唤 / 复活 | 真实继承与 Start、最终生成位置、旧批次回调隔离、恢复窗口和真实保护盾 |
| 资源 | 重复构建、原组件 / 共享资源完整性；时长增加后的重叠峰值 |

从[总目录](boss-deliverables.md)查对应菜单。执行 `工具/VFX/实战验收/<技能>` 后，通过 `工具/VFX/实战验收/结束并恢复` 收尾。新的菜单运行输出到 `ArtOutput/UI/Toolkit/<日期时间>/<phase>/`；收尾同时核对原场景、窗口、验收开关、输出目录和后台运行设置（包含 ProjectSettings 落盘值）。

一次改动运行受影响的检查；通过后，只有新的改动、失败或未解决的问题才需要扩大或重复测试。检查数量不是质量分数，相同报告在冲刺 / 小刀或分身 / 头标之间共用时不重复累计。

## 6. 输出能直接验收的交付包

每个技能留一段完整原速回放、一段局部预览、关键截图、数值 / 生命周期报告和已知限制。按帧捕获时间戳编码，注明镜头、测试条件和播放倍率；不要用加速 / 慢放或不同镜头冒充相同条件的精确对照。

现有 `render-boss-*-proof.cjs` 与 `audit-boss-*.cjs` 是各自版本的证据导出 / 完整性脚本，读取其固定历史目录。新一轮先配置新版本目录或扩展输出参数，再导出；不要在收尾时无差别重跑全部旧脚本覆盖历史证据。Sharp / FFmpeg 路径以本机环境为准。

提交观感时写“表现变化、机制变化、资源增量、验证结果、尚未覆盖项”，附录像。按任务约定逐项反馈再制作下一项；程序通过、观感确认、配表上线和真机通过分别记录。

## 7. 登记和复用

目录约定如下，已有文件保留原路径，使用索引串联：

```text
Tools/VFX/boss-production-workflow.md         工作流入口
Tools/VFX/boss-deliverables.json              人工维护的产出索引元数据
Tools/VFX/boss-deliverables.md                从索引生成的可点击交付目录
Tools/VFX/boss-production-prompts.md          可复制制作指令
Tools/VFX/Templates/boss-skill-brief.md       新任务单
Tools/VFX/Library/Boss/<id>.json              专用表现配方
Assets/Editor/Boss*Builder.cs                 构建与配置审查
Assets/Script/Game/Enemies/Boss/              技能模块和表现组件
Assets/ArtPreview/Skills/Boss*ValidationRunner.cs  真实技能夹具
ArtOutput/VFX/<任务>/                        任务单、原稿、基线和 Audit
ArtOutput/UI/<任务或Toolkit日期>/            报告、截图、原始帧和原速录像
```

收尾更新配方状态 / 报告路径、任务单、版本说明和 `boss-deliverables.json`。既有报告不回填成新一轮结论；观感确认以明确反馈为准。增加正式表技能分配时，同时更新索引的 `integration` 和 Boss 清单。

从工程根目录运行：

```powershell
node Tools/VFX/audit-boss-workflow.cjs --write-index
```

命令生成目录，核对索引与目录一致性、全部 Boss 配方覆盖、路径与实际菜单、历史报告的通过字段、相对文档链接，并将结果写到 `ArtOutput/VFX/BossWorkflow/Audit/catalog-check.json`。不带 `--write-index` 只检查并输出报告，目录过期会报错。该命令不会启动 Unity、重建 Prefab、改变技能配表、重新执行战斗或给真机结论盖章。`integration` 是人工维护的配表 / 接入记录，静态目录检查不能自动证明它符合 FlatBuffer 表。

## 后续延伸

独立免伤技能先验证真实减伤、类型、耗次、失效和缓存再制作持续壳体。Spine 主体迁移时复用世界空间危险范围与事件，但需要替换身体中心 / 头部 / 出手 / 后沿 / 受击锚点、分身重影和复活快照；当前只保留了头部绑定入口。

最终发布前，在固定微信机型、相同关卡和构建设置下补测帧时、内存、过绘及包体增量；这些结论独立于 Editor 的制作验收。
