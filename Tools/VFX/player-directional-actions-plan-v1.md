## 首轮收敛（2026-10-30）

用户担心动作数量过多，第一轮收敛为：**待机、跑步两套基础循环，叠加方向 / 瞄准和一次开枪回弹。** “站着开枪”“边走边射”是这些控制的组合，不分别增加一整套动画。先把移动、握枪和出手节奏做自然，再扩到完整八向、后退 / 横移细节和其余角色。

[13 秒参考视频](../../ArtOutput/VFX/PlayerActionReferenceV1/reference.mp4)使用内置 imagegen 的三向草图和离线分件动画，演示停留、走路、走路开枪和转向；这是动作节奏示意，非 Unity 实装、非最终角色美术。[样片说明](../../ArtOutput/VFX/PlayerActionReferenceV1/README.md)与[完整提示词](../../ArtOutput/VFX/PlayerActionReferenceV1/prompts.md)保留来源。以下五视角 / 八向方案作为后续完整目标，不是首轮一次性交付范围。

## 推荐路线

**五个关键视角原画＋左右镜像形成八向，头身手脚与武器分件，动作曲线复用，枪械按实际射击方向瞄准。** 第一版使用轻量 Transform 关节动画和方向 Sprite 切换，不要求引入 Spine，也不要求复杂蒙皮、IK 或布料。

方向变化需要补画真实侧面 / 背面，不能靠旋转正面图代替。帧动画可作为个别特殊姿态的补充，第一轮不批量生产八方向整身序列帧。分件资源节省了重复绘制整个人物的像素，代价是更多渲染部件、部位排序和美术拆分；以实战尺寸和设备测量决定最终取舍。

## 八方向如何少画资源

| 游戏方向 | 使用的关键视角 | 原画是否新增 |
| --- | --- | --- |
| 下 | 正面 | 是 |
| 右下 / 左下 | 前侧 45° / 镜像 | 一份 |
| 右 / 左 | 侧面 / 镜像 | 一份 |
| 右上 / 左上 | 后侧 45° / 镜像 | 一份 |
| 上 | 背面 | 是 |

只制作五个关键视角的部件，不为八个方向各画一套待机、跑步和射击整身帧。各视角有对应握持和前后遮挡关系；在方向内做有限瞄准调整，跨到前 / 侧 / 背时换相应枪与手姿，避免只把侧视枪图旋转 90° 冒充正对 / 背对镜头。

第一步先验证正面、侧面、背面三个方向的分件与握枪，再补前侧和后侧视角形成正式八向。三个方向仅用于早期样机，最终八向验收仍要求五视角到位。左右复用以视觉合理为前提，额带文字、徽章等非对称标记不随整图翻转。

## 弹仔应当怎样动

保留现有大头短身、红额带、深色衣服和厚轮廓，在实际镜头下强调手脚节奏与枪械重量。

| 状态 | 可见动作 | 首轮建议参数（待实测调整） |
| --- | --- | --- |
| 待机 | 胸腹轻呼吸，头部和额带尾部小幅延迟；枪口稳定 | 呼吸约 1.2～1.8 秒；高度变化不超过身高 H 的 1% |
| 移动 | 脚步交替、轻微压低 / 抬起身体，头部相位略晚；握枪手稳定 | 默认速度一个步态周期约 0.45～0.60 秒；身体上下幅度约 1～2% H |
| 开枪 | 发射当帧枪口短闪，枪与前臂沿射击反向回缩，肩膀轻震再回位 | 后坐约 0.04～0.06 秒，回稳约 0.08～0.14 秒；枪平移约 2～4% H |
| 边走边射 | 下半身继续迈步，上半身保持瞄准，后坐叠加在握枪上 | 枪 / 肩膀动作不重置腿部步态，不锁住移动 |
| 后退 / 横移 | 仍面向攻击方向，脚步表现后退或短侧步 | 按实际速度与当前朝向的相对方向驱动；不要求上半身拧转 180° |
| 受击 | 所有身体部件统一闪色 / 轻震，随后继续步态与持枪 | 沿用原有效受击事件，视觉位移不改变碰撞体 |

H 是当前角色世界可见高度，不是贴图全画布高度。所有幅度先在战斗尺寸看，放大图只检查接缝与抖动。高攻速时每次真实发射追加受控后坐脉冲并限制最大幅度，不把整段射击动作反复强制重播，也不延迟发射等动作播完。

## 移动与瞄准的规则

- 有主武器有效瞄准目标：头胸和枪表达主武器方向；移动速度与相对方向决定腿部前进、后退或侧移步态。
- 没有目标：朝实际移动方向；停下后保留最后朝向。
- 方向边界设约 6～10° 的切换缓冲，目标切换时保持短暂稳定；数值只影响视觉，不改变索敌和真实发射方向。
- 发射当帧以实际方向校正枪 / 手和火光，不能让平滑瞄准造成视觉打向旧目标。移动速度取墙体处理后的实际位移，贴墙原地推摇杆时不跑步，传送不产生巨大步幅。
- 只由角色的主武器驱动全身攻击动作。其他学到的自动技能继续播放自身特效，避免同一角色在一帧内被枪、飞刀、符箓反复切换姿态；多发散射是一轮动作，环绕爆发单独标记。

第一版枪口节点供火光与握持校准使用。当前真实弹体在玩家中心生成，若改为枪口生成，会改变贴墙、贴身与射程起点；应单独核对碰撞和出弹方向，不能只把物理起点随骨骼挪走。动画由真实发射驱动，伤害、冷却、弹数、速度与发射时刻保持原逻辑。

## 资源预算与复用

以下是首轮目标，不是已测量结果：

| 项目 | 建议起点 | 需要扩大时的条件 |
| --- | --- | --- |
| 单角色正式图集 | 优先 512×512，一张图集放五视角部件和主武器 | 实际尺寸下头脸、持枪和接缝不足再试 1024×512；不默认上 2048 |
| 新源 PNG | 弹仔先争取约 128～256 KiB | 实际透明图打包后记录字节；不能提前承诺所有角色都达到同一压缩率 |
| 单角色活动部件 | 约 6～10 个 SpriteRenderer，另加简单共享阴影 | 额带文字和前后手排序按需要设置；实测渲染开销 |
| 动作层级 | 约 10～14 个 Transform 关节 | 第一版不加复杂 IK、布料、大量面部骨骼或骨骼特效 |
| 动作数据 | 待机、步态、射击、受击四组基础曲线 | 按视角调整原点、握持和排序；不重复储存五套整身帧 |
| 材质与载入 | 尽量共享原 Sprite 材质；战斗按当前角色引用 / 装载 | 图集组织与 Addressables / 资源加载是两件事，不能仅凭拆成五张图就宣称只加载一人 |

在 ETC2 RGBA8、无 mipmap 前提下，512×512 纹理块数据约 256 KiB，1024×512 约 512 KiB；PNG 文件大小、Unity 内存和微信最终包体另测。全五人若各一张前者，理论纹理块合计约 1.25 MiB，后者约 2.5 MiB；不包含字体、特效、其他纹理、运行对象和加载缓存，也不代表它们应同时驻留。

同图集 / 共享材质有助于减少纹理切换，但分件不自动等于一个 draw call。透明排序、部件遮挡和实际批处理需在当前 Built-in 工程测量。若远景下分件接缝、文字清晰度或渲染成本不理想，可对个别关键姿态用少量替换 Sprite；确需烘焙帧时另列实际收益与纹理成本。

五个角色共享动作事件规范、方向判定、速度驱动、受击、暂停与预览工具；比例与武器姿态保留各自修正。弹仔做瞄准 / 后坐基准，飞刀与符箓复用甩手动作框架但保留不同手势，炸弹增加抬臂 / 抛掷，导弹按实际角色设计采用肩扛或背部装置的发射反馈。角色体型和骨架不同，不能承诺仅换皮就完全复用所有曲线。

## 分阶段交付与验收

1. **姿态样板：**弹仔正 / 侧 / 背方向拆件和持枪检查，补齐前侧 / 后侧后交付八向静态板。先确认头身比、脸、枪、左右文字和遮挡关系。
2. **基础动效：**一个方向的待机、移动、开枪、边走边射；在原地图上观察实际大小、脚底固定、后坐力度和高速连射。
3. **八向接入：**方向切换、横移 / 后退、目标切换和多武器优先级；沿用真实射击时刻，分开验证枪口视觉与原判定。
4. **真实战斗与资源：**浅沙 / 草地、八向环绕目标、贴墙、贴身、高攻速、散射 / 爆发、受击、暂停、死亡 / 重开、角色更换；记录角色对象 / 材质 / 纹理是否增长，测量实机帧时、内存与同设置包体增量。
5. **定型后扩展：**按相同接入规范扩到飞刀、符箓、炸弹和导弹；每人保留一段原速实战、动作参数、图集预算和已知差异。当前提案不开始五人批量生产。

验收输出：八向姿态板、一段完整原速移动 / 射击录像、一段局部回放、真实发射 / 方向同步报告和资源统计。通过程序检查、观感确认与真机通过分别记录。

## 技术依据

- 本工程配置和实现以上方源码 / Prefab 为准。已有工具包不代表角色动作已接入。
- [Unity 2D Animation 7 Sprite Swap](https://docs.unity.cn/Packages/com.unity.2d.animation@7.0/manual/SpriteSwapIntro.html)：方向 / 部件切换可利用现有工具；骨骼蒙皮 Sprite 复用要求骨架一致。同一 Animator 混用 SpriteRenderer.sprite 与 SpriteResolver 键动画有冲突限制，实施时统一由一条入口负责换向。
- [Unity 2021.3 Sprite Atlas 参数](https://docs.unity3d.com/2021.3/Documentation/Manual/class-SpriteAtlas.html)：图集大小、padding、旋转、mipmap、CPU 可读及平台压缩分别核对。像素轮廓与拼接效果以工程实拍为准。
