## AI 协作方式（必须遵守）

**接到与本仓库相关的任务时，须通读并遵守本文档；不得因赶进度跳过澄清与确认步骤。**

### 协作方式
1. 收到需求后不要立即执行。通过持续提问来澄清需求，不限制问题数量，直到你确信自己完全理解了我的意图。
2. 每个问题尽量具体，可以给出选项或参照物，但不要替我做选择。
3. 确认充分后再开始执行，严格按照确认后的需求交付。
4. 在交付内容之外，可以附上你的创意建议，但必须明确标注为"可选"，并说明利弊，最终由我决定是否采纳。
5. 如果在执行过程中发现新的模糊点，停下来继续问，不要猜测。
### Debug 问题定位
1. 加日志自动输出日志文件。
2. 问题解决后清空日志文件。
### UI 弹窗（必须遵守）
1. **在对话里直接生成弹窗相关代码时**：应优先对照工程内**已有弹窗**（Prefab 层级、`UIPanelBase` 子类、按钮/列表与 `UIManager` 的注册方式等），沿用相同结构与命名习惯，避免另起一套互不衔接的拼 UI 方式。
2. **若弹窗布局复杂、或你希望由编辑器精确摆放控件与引用**：请你**先在 Unity 里创建/摆好 UI**（含节点层级、组件、SerializeField 引用能绑则先绑），再说明需要接线的脚本职责与数据流；我据此**只写或补全脚本与逻辑**，不在未约定的情况下擅自用纯代码大规模「现场拼」整套界面。

### Unity 资产与 .meta（必须遵守）

Unity 内 Prefab、Scene、ScriptableObject 等**引用脚本/资源用的是 `.meta` 里的 GUID，不是文件路径**。违反下列约定会导致 Missing Script、特效不播、IDE 报「找不到类型」等难查问题。

1. **新建脚本/资源时**
   - AI **只创建 `.cs`（或约定好的非 Unity 资产文件），不创建、不手搓 `.meta`**。
   - **禁止**伪造 GUID（含位数不对、重复、从别的项目抄来的 ID）。
   - 交付后说明：**请切到 Unity 等待 Asset Database 自动 Import**，由 Unity 生成 `.meta` 后再继续绑 Prefab / SO。

2. **已有资产的 `.meta`**
   - **不得删除**已有 `.meta` 指望 Unity「刷新重建」——GUID 会变，所有旧引用断裂。
   - 需要改 Prefab / SO / Scene 里的脚本引用时，**必须先读取 Unity 已生成的对应 `.cs.meta` 中的 `guid`**，不得臆造。

3. **工程文件**
   - **不手改** `Assembly-CSharp.csproj` 等 Unity 生成的工程文件；IDE 报红时提示用户在 Unity 中 **Regenerate project files** 或聚焦 Editor 触发 Refresh。

4. **Git**
   - `.cs` 与 `.meta` **成对提交**；`.meta` 不得加入 ignore。

5. **推荐顺序（Claude 写代码 → Unity 绑引用）**
   ```
   Claude 新建/修改 .cs → Unity Import 生成 .meta → 确认 Console 无编译错
   → 再改 Prefab / SO 引用（或用户在 Inspector 里拖拽绑定）
   ```

- 尊重：我的选择优先，你的建议是补充，我提出新想法时，强制先向我提出3个犀利的反问
- 启发：用小巧思打开我的思路，但不要替我做决定
